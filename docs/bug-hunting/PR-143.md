## Scope

PR #143 is limited to provenance metadata in the read-only DXF-to-DXF comparator. It records SHA-256 hashes for both input files and the ezdxf version used. It does not change conversion providers or architectural understanding.

## Bug Hunt

The comparison report previously described structural differences but did not identify the exact byte-level inputs or parser version. This made later reproduction and audit less reliable. The change adds bounded streaming SHA-256 calculation and parser-version metadata. The comparator remains read-only; fidelity remains UNKNOWN and review is mandatory.

## Findings

- Both input hashes are computed from the exact files passed to the comparator using 1 MiB chunks.
- The ezdxf runtime version is included in successful comparison reports.
- No input file is written, renamed, or replaced.
- A successful supported-content comparison is not proof of DWG conversion fidelity.
- The report must retain fidelity UNKNOWN and requires_review=true.
- No provider selection, ODA execution, or Windows-specific behavior is changed.
- No PlanModel, ConstraintMap, ApprovedChangePlan, BIM, or architectural semantic contract is modified.

## Reproduction

Create two synthetic DXF files and run:
python -m unittest tests.test_dxf_comparator -v

Inspect the report fields source_sha256, candidate_sha256, and ezdxf_version. Independently hash the original bytes with hashlib.sha256 and compare the expected hex digests.

## Root Cause

The previous report omitted provenance fields. A comparison result without exact input hashes and parser version is harder to reproduce, especially when DXF files are regenerated or library behavior changes between versions.

## Regression

A new regression assertion verifies that both reported SHA-256 values match the exact source and candidate byte sequences and that ezdxf_version is populated. Existing tests continue to cover geometry differences, unit differences, tolerance, malformed input, dimensions, HATCH, SPLINE, attributes, Xrefs, and read-only behavior.

Hashing is streaming and bounded to 1 MiB per read; it does not load the entire drawing into memory. Parse errors remain fail-closed. The hash fields are populated for successful comparisons; parse failures still return COMPARISON_FAILED and fidelity UNKNOWN.

## Required fail-closed states

Any file access or parse failure remains COMPARISON_FAILED. Missing/ambiguous geometry support remains INCOMPLETE. No comparison result may promote conversion fidelity to PASS. The report remains fidelity UNKNOWN and requires review (NEEDS_REVIEW). Unsupported content must not be treated as equivalent. A missing provenance value must not be fabricated.
