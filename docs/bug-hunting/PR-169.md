# Bug Hunt — H101 GeometryReference model binding (PR 169)

## Scope
Attach the existing source-bound GeometryReference contract to canonical PlanModel and SpaceModel, and preserve it through PlanModel reconstruction. No geometry conversion, normalization, architectural semantic promotion, or editing capability is added.

## Bug Hunt
The integration creates new cross-contract paths where a geometry reference might be attached to the wrong drawing source, dropped during reconstruction, or bypassed through optional model construction. Source identity must remain exact and all existing callers must remain compatible when the reference is omitted.

## Findings
- PlanModel previously had no direct GeometryReference attachment.
- SpaceModel and its builder previously had no GeometryReference attachment.
- Reconstruction previously had no parameter to carry geometry provenance forward.
- Source SHA mismatch at any attachment boundary could associate units/transforms with unrelated drawing geometry.
- Backward compatibility is required because existing PlanModel/SpaceModel callers omit GeometryReference.

## Reproduction
New tests attach one GeometryReference to both models and validate it; attempt mismatched source hashes in SpaceModel, PlanModel, and reconstruction; and instantiate legacy models without GeometryReference. The tests are expected to prove source mismatch rejection and optional-field compatibility.

## Root Cause
H101's geometry contract was standalone. PlanModel and SpaceModel had source-hash validation for their own evidence, but there was no first-class field or construction path for GeometryReference. The evidence-backed coordinate interpretation was therefore not carried in the canonical plan models.

## Regression
Added H101 integration coverage for:
- shared reference attachment and identity preservation across PlanModel and SpaceModel;
- source-hash mismatch rejection by each model;
- reconstruction preserving the GeometryReference;
- reconstruction rejecting mismatched source SHA;
- legacy model creation with no GeometryReference.

Existing H63 PlanModel-SpaceModel integration and reconstruction tests remain relevant regression coverage and must run on this exact head.

## Required fail-closed states
- Missing geometry provenance remains UNKNOWN and cannot authorize metric area conversion.
- Cross-source attachments remain NEEDS_REVIEW or are rejected; no false promotion occurs.
- Source mismatch is rejected with a validation error.
- No units or transforms are applied by this integration.
- No architectural element/space/relation status is promoted.
- PASS applies only to software checks, not geometry correctness.
- No false pass is allowed.
