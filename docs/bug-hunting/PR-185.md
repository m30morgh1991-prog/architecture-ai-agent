## Scope

POL-01: change runtime error classification to fail closed. Only exact allowlisted non-blocking code TARGET_NOT_FOUND remains NON_BLOCKING; unknown, malformed, empty, non-string codes and suffixed variants block. Known blocking codes and their colon-suffixed variants remain BLOCKING.

## Bug Hunt

The previous deny-list behavior classified any code not in BLOCKING as NON_BLOCKING. That made unknown and malformed error codes permissive and allowed a suffixed LOCKED_ELEMENT_CONFLICT to bypass exact membership.

## Findings

POL-01: unknown failure codes defaulted to NON_BLOCKING; code suffix variants of known blocking failures could also be misclassified. The patch now uses an explicit non-blocking allowlist and fail-closed default.

## Reproduction

Test-first: added tests for unknown codes, empty/null values, malformed suffixes, and LOCKED_ELEMENT_CONFLICT with an element suffix. The pre-fix snapshot failed these cases (6 assertion failures). After the fix, the focused tests passed (5 tests).

## Root Cause

The classifier was implemented as a blocking deny-list: if a code was not present in the set, it was assumed safe. This is an unsafe assumption when new codes, malformed values, or structured suffixes are introduced.

## Regression

Existing behavior for exact LOCKED_ELEMENT_CONFLICT and TARGET_NOT_FOUND is preserved. Unknown codes and suffixed LOCKED_ELEMENT_CONFLICT are now blocking. Focused local tests: 5/5 passed after the patch.
