# Bug Hunt — H75 change-type/target-type guard (PR 163)

## Scope

Harden deterministic impact analysis so furniture-only change requests cannot target non-furniture architectural elements, even if a supplied ConstraintMap incorrectly lists a structural element as EDITABLE.

## Bug Hunt

Review focused on mismatch between the requested change domain and the actual PlanModel element type. ImpactAnalysis already declared the editable change types, but the allowlist was not used to verify target element types.

## Findings

- `_EDITABLE_TYPES` declared FURNITURE and FURNITURE_LAYOUT_CHANGE but was not enforced.
- ImpactAnalysis relied on ConstraintMap buckets alone for direct target authorization.
- A malformed or misclassified ConstraintMap could list a WALL/COLUMN/WINDOW/DOOR as editable and cause a furniture request to proceed.
- A target-type mismatch is a deterministic blocker, not a review-only condition.
- No false pass is allowed.

## Reproduction

Use a PlanModel containing a WALL element and a ConstraintMap that incorrectly places that wall ID in `editable_element_ids`. Submit a FURNITURE_LAYOUT_CHANGE request targeting the wall. Before the fix, the impact analysis could classify it as a direct editable target and return PASS.

## Root Cause

The impact-analysis contract did not cross-check the request's change domain against the target element's canonical PlanModel type. It trusted the editable ConstraintMap bucket without enforcing the already-declared furniture-only change policy.

## Regression

Added a negative test that deliberately misclassifies a WALL as editable in ConstraintMap and verifies that a furniture request returns BLOCKED with `CHANGE_TYPE_TARGET_TYPE_MISMATCH`. Existing furniture-positive, protected-target, unknown-target, source-mismatch, overall-layout, and BIM-neighbor tests remain.

## Required fail-closed states

- UNKNOWN: target/model/evidence is missing or unresolved.
- NEEDS_REVIEW: broad architectural layout requires rule review.
- BLOCKED: a furniture change targets any non-FURNITURE PlanModel element.
- PASS: only a furniture target explicitly editable in ConstraintMap may pass this target-type check.
- No false pass from a malformed or misclassified ConstraintMap.
