# H97: runtime evidence integration

## Scope
Expose real execution audit, idempotency, and runtime completion evidence so the hardened H96 release gate can evaluate the actual execution path.

## Bug Hunt
### Reproduction
The H96 release gate correctly requires explicit audit, idempotency, and runtime evidence. The HTTP execution path did not surface those evidence signals after a completed execution, leaving the real runtime unable to prove its own readiness.

### Root Cause
Evidence existed internally:
- AuditTrail computed audit completeness.
- IdempotencyGuard stored completed results.
- Execution status represented runtime completion.

But these signals were not returned as explicit release-gate evidence.

### Fix
- Expose audit_complete and strict audit_ok from the execution path.
- Expose runtime_ok only when final execution status is PASS.
- Expose idempotency_ok only after the completed result is stored.
- Persist the enriched result in the idempotency cache so replay returns the same evidence.

## Regression
Permanent tests verify:
1. successful execution exposes all required evidence;
2. blocked execution cannot claim audit/runtime PASS.

## Fail-Closed
UNKNOWN, BLOCKED, rejected, incomplete, or missing evidence remains non-PASS.

## CI Verification
Required: Bug Hunt Gate, Runtime Tests, PR CI Gate all completed/success on the final H97 head.

## Final Decision
Do not merge H97 until exact-head CI is green and the post-merge main CI result is observable.
