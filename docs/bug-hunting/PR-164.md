# Bug Hunt — exact boolean evidence for final and production gates (PR 164)

## Scope

Harden final validation, visual release, production readiness, and controlled-editing E2E contracts so truthy non-boolean values cannot satisfy a PASS/READY gate. No new capability or geometry editing behavior is introduced.

## Bug Hunt

Review focused on Python truthiness, direct dataclass construction, source identity validation, and caller-provided evidence flags.

## Findings

- `FinalValidationContract.evaluate_final_validation` previously used `bool(...)` for approval, post-edit validity, before/after validity, and audit completeness. A non-empty string such as `"false"` therefore became True.
- `FinalValidationContract.validate` did not verify that all required checks were exactly True before accepting a directly constructed PASS object.
- `evaluate_final_gate` used `bool(...)` across all invariants, allowing truthy non-boolean values to satisfy the gate.
- `evaluate_production_readiness` used `bool(...)` for required checks; a string `"false"` could be recorded as a successful check.
- `evaluate_visual_release` relied on ordinary truthiness for boolean gates.
- `ControlledEditingE2EGate.validate` did not enforce an actual bool for `executable` and accepted any non-empty source identifier.

## Reproduction

Pass `approved="false"`, `audit_complete="false"`, or `runtime_release_ok="false"` to the relevant gate. Before the fix, Python's truthiness conversion could treat these non-empty strings as True. Separately, construct a FinalValidationContract or ProductionReadinessResult directly with status PASS and one failed check; the old validators did not fully verify the checks dictionary.

## Root Cause

Several gate boundaries treated typed evidence as generic truthy values. Dataclass annotations do not enforce runtime types, and direct construction bypassed helper-level assumptions. PASS validation also failed to re-check all required evidence fields.

## Regression

Added tests verify:
- Truthy strings cannot replace boolean evidence in final validation, audit E2E, visual release, or production readiness.
- FinalValidationContract direct PASS with a false check is rejected.
- ProductionReadinessResult direct PASS with a false check is rejected.
- ControlledEditingE2EGate rejects string executable values and malformed source hashes.
- Source SHA-256 must be a canonical lowercase hexadecimal 64-character digest before final PASS.
- Scope identifiers must be valid collections of unique non-empty strings.

## Required fail-closed states

- UNKNOWN: source or evidence is missing.
- NEEDS_REVIEW: valid but uncertain post-edit/before-after evidence.
- BLOCKED: invalid boolean type, malformed source identity, failed gate, invalid scope, or failed audit.
- PASS: only when every required evidence field is exactly the boolean `True`.
- No false pass from Python truthiness or direct dataclass construction.
