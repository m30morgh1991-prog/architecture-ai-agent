# Bug Hunt — strict H69/H100 evidence numeric integrity (PR 159)

## Scope

Harden existing source-bound evidence contracts against boolean-to-number coercion, non-finite supported measurements, and malformed source SHA-256 values. No new architecture feature, detector, parser, provider, or editing capability is introduced.

## Bug Hunt

The audit found that Python treats booleans as integers. Existing confidence validators accepted `True` as confidence 1.0, and builders converted boolean confidence to float before validation. Supported dimension and level validators checked only positivity/presence; NaN comparisons can bypass ordinary less-than checks. Several evidence contracts accepted any 64-character source identifier rather than a canonical SHA-256 hex digest.

## Findings

- H69 `ElementEvidence.validate` accepted boolean confidence values.
- `build_element_evidence_bundle` converted confidence using `float()`, so `True` became 1.0 before validation.
- H100 `DrawingEvidence.validate` had the same boolean-confidence weakness, and its builder also coerced values before validation.
- H100 `DimensionEvidence` could accept NaN as a supported positive dimension because `NaN <= 0` is false.
- H100 `LevelEvidence` could accept NaN as a supported elevation because only presence was checked.
- H69 and H100 source-hash checks validated string length but not lowercase hexadecimal SHA-256 syntax.
- These gaps could create invalid evidence objects that appear structurally supported; this is a false pass risk.

## Reproduction

Run the H69 and H100 contract tests. The new regression cases pass `True` as confidence, use a non-hex 64-character source hash, and provide NaN/Infinity/boolean values for supported dimensions and elevations. Before the fix, boolean confidence and non-finite dimension/elevation values could pass the relevant validators.

## Root Cause

The contracts relied on Python numeric comparison and permissive `float()` coercion rather than explicitly excluding booleans, requiring finite numeric values, and validating canonical source-hash syntax.

## Regression

Added tests verify:
- Direct and builder-created H69 evidence reject boolean confidence.
- H69 evidence rejects non-hex source hashes.
- Builder-created H100 evidence rejects boolean confidence before numeric coercion.
- H100 evidence sets reject non-hex source hashes.
- Supported dimensions reject NaN, Infinity, and booleans.
- Supported levels reject NaN, Infinity, and booleans.
- Existing valid H69/H100 evidence remains accepted.

## Required fail-closed states

Malformed numeric values or source identities are rejected. UNKNOWN, NEEDS_REVIEW, and BLOCKED remain unresolved. PASS is never inferred from coercion or a merely 64-character source identifier. No false pass is allowed.
