## Scope

Extend the existing read-only DXF comparator to compare STYLE and DIMSTYLE table records. This is planned CAD metadata coverage, not a new text-correction or font-rendering feature.

## Bug Hunt

The comparator previously compared text content and style names attached to entities, but it did not compare the definitions behind those names. A STYLE record can point to a missing or different SHX/bigfont file, and a DIMSTYLE record can carry different text heights, arrow sizes, units and display rules while entity geometry remains identical.

## Findings

- Text STYLE records are compared, including font and bigfont filename references.
- DIMSTYLE records are compared with deterministic normalization of numeric and string values.
- Handles and owner references are excluded from semantic comparison.
- Style differences are reported as structural differences and do not become model-geometry mismatches.
- Missing SHX files are not loaded or substituted; the DXF filename reference is compared as metadata only.
- No RTL reversal, Unicode normalization, KATEB emulation, font repair or print-rendering claim is introduced.

## Reproduction

Run:
- `python -m unittest tests.test_dxf_comparator -v`

Synthetic fixtures create DXFs with different SHX/bigfont references and dimension-style text-height properties while keeping model geometry identical. They assert the relevant style difference and a MATCHED geometry status.

## Root Cause

Entity-level signatures alone do not capture all drafting semantics. Style table records are shared dependencies that can alter how text and dimensions appear without changing the underlying entity coordinates.

## Regression

Permanent tests cover missing/different SHX style references and DIMSTYLE property changes. Existing regression coverage for Persian text resilience, layouts, viewports, UCS, extents, units, layers, blocks, nested INSERTs and geometry remains required.
