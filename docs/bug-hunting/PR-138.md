## Scope

PR #138 adds a standalone GeometryReference contract and focused tests. No parser, geometry mutation, unit normalization, PlanModel integration, or Windows/AutoCAD host behavior is changed.

## Bug Hunt

Review focused on false unit conversion, paper/model scale confusion, unsupported evidence promotion, malformed transforms, and source provenance. The principal false pass risk is treating a unit label, paper scale, or transform matrix as proof without source evidence.

## Findings

- Geometry units and paper scale must remain separate.
- A paper scale such as 1:100 must not be applied to model-space coordinates.
- A declared unit without SUPPORTED status and source-matched evidence records must not enable square-metre conversion.
- Raster calibration must reject singular and non-finite transforms, and the homogeneous final row must identify a true affine matrix rather than a projective transform.
- OCS/WCS and nested INSERT transforms remain unresolved and outside this PR.

## Reproduction

The negative tests construct unsupported units, unsupported coordinate frames, missing paper-scale ratios, singular raster transforms, non-finite transform values, duplicate evidence IDs, and invalid source hashes. These are deterministic contract-level reproductions; no native DWG parsing is claimed.

## Root Cause

The current understanding contracts do not have a single explicit geometry-reference object that separates linear unit, coordinate frame, sheet scale, raster calibration, and dimension reconciliation. This gap makes accidental conflation possible at future integration points.

## Regression

The new tests verify that UNKNOWN unit status cannot authorize metric area, that evidence IDs resolve to records bound to the same source SHA and correct domain, that uncertain evidence cannot authorize SUPPORTED status, that paper scale does not establish model units, and that malformed or unsupported calibration evidence is rejected. The implementation is additive and leaves existing geometry paths unchanged.

## Required fail-closed states

UNKNOWN, NEEDS_REVIEW, and BLOCKED remain valid outcomes. Unsupported or contradictory evidence must never be promoted to SUPPORTED or PASS. No compliance or editing permission follows from this contract.

## Follow-up code review — fail-closed constructor and transform validation

A deeper review found that the public `GeometryReference` dataclass could be instantiated directly without calling `validate()`. In that case, `square_metre_factor` and `can_report_area_m2` could report a conversion factor from `unit_status=SUPPORTED` even when no matching evidence records existed. This was a real false-pass path at the public contract boundary.

The dataclass now validates itself during construction, so direct construction cannot bypass evidence checks. Evidence records now reject non-string/blank IDs, source references and values, and malformed/non-canonical source hashes. Collection inputs reject strings instead of coercing their characters into tuple members. The 4x4 coordinate transform is now required to be affine and nonsingular; the 3x3 pixel transform uses a relative singularity check so small but valid pixel scales are not rejected by an absolute determinant threshold.

Regression tests now cover direct-constructor bypass, blank evidence values, projective and singular 4x4 transforms, small valid pixel scales, and string-to-matrix coercion. These are contract-level tests only; no DWG parser, geometry transform application, PlanModel integration, or Windows/AutoCAD host test is claimed.

## Risk Classification

Medium integration risk, low immediate runtime risk. The contract is not yet wired into PlanModel/SpaceModel. False pass risk is specifically metric conversion without supported unit evidence or paper-scale leakage into model coordinates.

## Negative Tests

- Missing evidence for a SUPPORTED unit is rejected.
- Evidence IDs without a matching source-hash-bound record, or with the wrong domain, are rejected.
- UNCERTAIN evidence cannot be used to claim SUPPORTED unit/frame/scale/dimension/transform status.
- Missing evidence for a SUPPORTED coordinate frame is rejected.
- Paper scale without a ratio is rejected.
- Raster calibration without an affine transform is rejected.
- Singular, non-finite, boolean, and projective transform values are rejected.
- Duplicate evidence IDs and invalid source hashes are rejected.

## Unresolved Findings

DWG header-to-geometry unit reconciliation, OCS/WCS resolution, nested INSERT transforms, PDF page calibration, raster pixel-to-world calibration, and dimension-to-geometry reconciliation remain unresolved findings. The raster matrix contract now rejects projective 3x3 matrices; actual source calibration remains unimplemented. These require separate source adapters and golden regression evidence.

## Follow-up — reject numeric-string transform coercion

Review found that the transform validator rejected booleans and non-finite values but converted numeric strings such as "1.0" to floats. This differs from the strict numeric contract used by SpaceModel and could hide malformed serialized geometry. The validator now accepts only real numeric values (excluding bool), converts them to finite floats, and adds negative tests for both 3x3 raster and 4x4 coordinate transforms. This is validation hardening only; it does not apply transforms or change geometry.
