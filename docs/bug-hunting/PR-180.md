## Scope

Correct the critical unsafe mainline HTTP runtime by porting consolidated runtime hardening and an HTTPS-only TLS/auth boundary directly onto current main. This PR removes the unsafe all-interface plaintext listener and retains execution as BLOCKED until server-owned canonical evidence and approval exist.

## Bug Hunt

Inspect transport enforcement, startup configuration, authentication, body handling, audit/idempotency lifecycle, untrusted payloads, and regressions in the fail-closed boundary.

## Findings

- Main had an unauthenticated plaintext listener bound to `0.0.0.0:8000`; client JSON could create PlanModel and state values.
- The corrected candidate requires certificate/key and a strong bearer secret at startup; TLS 1.2 minimum.
- HTTPS is loopback-only at `127.0.0.1:8443`; there is no plaintext HTTP listener, redirect, fallback, or dormant HTTP execution handler.
- Execution-record lookup is read-only and authenticated.
- POST /v1/execute returns BLOCKED before reading the request body; client self-asserted EDITABLE and geometry cannot reach an execution handler.
- Audit and idempotency lifecycle/request-validation hardening is ported from the reviewed consolidated candidate.

## Root Cause

Main retained an unsafe legacy plaintext runtime. Stacked #173/#174 could leave a merge-order gap and #173 alone retained HTTP remnants. This corrective branch ports the combined boundary directly from main and removes the dependency on the stack for the critical fix.

## Regression

- Startup without TLS configuration or a strong bearer token fails closed.
- TLS is enforced; trusted test certificate/IP-SAN succeeds and untrusted certificate fails.
- Missing or duplicate Authorization headers cannot access execution records.
- Authenticated GET remains read-only.
- Forged EDITABLE payloads are rejected before body consumption.
- Idempotency/audit false PASS conditions and malformed payloads are covered by regression tests.
- No HTTP listener, redirect, fallback, or execution handler is permitted.
