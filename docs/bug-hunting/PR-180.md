# Bug Hunt Evidence — PR 180 HTTPS-Only Fail-Closed Runtime on Current Main

## Scope

Port the HTTPS-only, loopback-only, authenticated read-only runtime boundary and consolidated audit/idempotency hardening onto the current mainline after PRs #178 and #179. Remove the unsafe all-interface plaintext HTTP listener. Keep POST /v1/execute BLOCKED before request-body consumption until server-owned canonical architectural evidence and the complete approval pipeline exist.

## Bug Hunt

Review focused on transport security, TLS startup, bearer authentication, request/body handling, audit lifecycle, idempotency fingerprints, workflow terminal states, response serialization, and the canonical execution fail-closed boundary.

## Findings

- Current main before this PR bound a plaintext HTTP listener to 0.0.0.0:8000 and accepted client-supplied plan/state payloads.
- The candidate requires explicit TLS certificate/private-key paths and a bearer token of at least 32 UTF-8 bytes at startup.
- TLS 1.2 minimum; HTTPS listener binds only to 127.0.0.1:8443. No plaintext HTTP listener, redirect, fallback, or dormant HTTP execution handler is retained.
- Execution-record GET is read-only and requires exactly one valid bearer Authorization header.
- POST /v1/execute returns HTTP 503 / BLOCKED before reading the body; client-supplied geometry, EDITABLE labels, and approval assertions cannot reach an execution path.
- Audit rejected-execution behavior, idempotency request fingerprint binding, terminal workflow replay, duplicate JSON key validation, and nested dataclass serialization are covered by regression tests.
- TLS integration tests exercise a real local handshake, trusted certificate/IP-SAN verification, rejection of an untrusted certificate, and missing-token rejection.
- This PR does not authorize remote/LAN access, CAD writes, or production execution.

## Root Cause

Mainline retained a legacy unauthenticated plaintext HTTP listener bound to all interfaces. Earlier stacked runtime hardening PRs did not provide a safe merge-order path to the current mainline and left security remediation dependent on stacked merge sequencing. This branch ports the consolidated boundary directly onto the latest main.

## Regression

- Missing TLS certificate/key or missing/weak bearer token prevents startup.
- TLS minimum is 1.2 and the listener binds only to 127.0.0.1:8443.
- Missing, duplicate, malformed, or incorrect bearer credentials are rejected.
- No plaintext HTTP listener, redirect, fallback, or dormant execution handler exists.
- POST execution remains HTTP 503 / BLOCKED before request-body consumption.
- Invalid payloads, duplicate JSON keys, non-finite values, malformed fields, and oversized bodies are not allowed to authorize execution.
- Idempotency keys cannot be reused with a different canonical request fingerprint.
- A RUNNING/UNKNOWN workflow decision is not treated as completed; terminal replay returns the terminal decision.
- Rejected execution cannot create an EXECUTE PASS audit record.
- Nested dataclass responses serialize deterministically.
- The false pass condition—representing an unvalidated/rejected operation as successful—is covered by explicit negative regression tests.
- No remote access, CAD write, legal compliance PASS, or H-stage advancement is enabled.

## Required fail-closed states

UNKNOWN, SOURCE_REQUIRED, NEEDS_REVIEW, ABSTAIN, and BLOCKED remain unresolved states and never become PASS without evidence. The HTTP execution endpoint remains BLOCKED until source-bound server-owned PlanModel/ConstraintMap, impact/conflict analysis, explicit approval, controlled editing, post-edit diff, final validation, and audit integration are implemented and independently reviewed.
