# Bug Hunt Evidence — PR 188 DOS-01 Bounded HTTPS Runtime

## Scope

DOS-01: prevent a slow or stalled local HTTPS client from monopolizing the runtime's only request-handling thread, and bound concurrent request handling. This is a stacked change based on PR #180's HTTPS-only loopback runtime branch; it must not be retargeted to main until its dependency is integrated.

## Bug Hunt

The review examined the synchronous request-serving boundary, accepted-connection lifetime, worker creation, listen backlog, TLS wrapping, and fail-closed endpoint behavior.

## Findings

The PR #180 candidate used the synchronous `HTTPServer`. A client that stalled during TLS/request processing could block the sole server loop. The accepted connection had no explicit socket timeout, and changing to an unbounded threaded server alone would replace a single-worker denial-of-service risk with unbounded thread/resource consumption.

## Reproduction

Before the change, the HTTPS runtime used the synchronous HTTPServer and accepted connections without a finite socket timeout. A stalled client could hold up the only request-serving loop. The regression checks require a bounded threaded server, explicit worker ceiling, finite socket timeout, daemon threads, and bounded backlog.

## Root Cause

The prior server serialized request handling on one thread and did not apply an accepted-connection timeout. A naive threaded replacement would permit unbounded thread creation, so concurrency must be capped before worker creation.

## Regression

- Use `ThreadingHTTPServer` so one slow request does not block all other request handling.
- Acquire a non-blocking bounded semaphore before starting a worker; excess connections are closed rather than spawning additional workers.
- Set a finite timeout on every accepted connection.
- Use daemon request threads and a bounded listen backlog.
- Preserve HTTPS-only TLS 1.2+, loopback-only binding to `127.0.0.1:8443`, bearer authentication, and the blocked POST endpoint.
- The POST endpoint remains BLOCKED before consuming request bytes; this PR does not add a body parser or execution path.

## Affected Contracts

- `runtime/app.py` — HTTPS request server concurrency, accepted-connection timeout, worker semaphore, listen backlog.
- `tests/test_http_request_guardrails.py` — server configuration and timeout regression checks.
- HTTPS/TLS, loopback-only binding, bearer authentication, and blocked POST behavior remain unchanged.

## Risk Classification

Moderate: the change alters runtime request scheduling and resource ceilings. It is deliberately bounded and keeps the execution endpoint disabled, but needs representative load testing before deployment.

## Limits

The worker cap is 8, socket timeout is 5 seconds, and listen backlog is 16. These are conservative initial runtime guardrails, not benchmark-derived production capacity settings. They require load testing on supported target environments before any remote deployment. Remote/LAN access remains disabled.

## Negative Tests

- Runtime server construction must use the bounded threaded server while preserving loopback address and port.
- Server class must expose daemon worker threads and bounded backlog.
- Every accepted connection receives the finite socket timeout.
- The concurrency ceiling and timeout constants remain explicit and test-checked.
- Existing TLS handshake, bearer authentication, POST-before-body-read, and runtime tests must remain passing.

## Required fail-closed states

Resource saturation must not create an execution, authorization, or false pass result. Excess connections are closed. POST execution remains BLOCKED. UNKNOWN, SOURCE_REQUIRED, NEEDS_REVIEW, ABSTAIN, and BLOCKED never become PASS.

## CI Verification

PR CI Gate, Runtime Tests, and Mandatory Bug Hunt must all complete successfully on the exact final head SHA. The PR must remain stacked on PR #180 until that base is integrated; do not treat its green checks as evidence that the change is independently mergeable onto main.

## Unresolved Findings

- The values 8 workers, 5 seconds, and backlog 16 are initial conservative limits; representative load/slow-client testing remains required.
- Operational certificate/key permissions, secret lifecycle, rate limiting, origin/CSRF controls, and independent security review remain outstanding as documented by PR #180.
- Windows/AutoCAD host and visual runtime tests remain NOT_RUN.
- No remote/LAN access or CAD execution is authorized.

## Final Decision

Implementation candidate only. BLOCKED pending exact-head CI, diff review, and successful integration of its PR #180 dependency. No approval, merge, or auto-merge is performed.
