# Bug Hunt — H100 DWG Evidence Reconciliation Bridge

## Scope
Verify that the new DWG evidence bridge normalizes read-only CAD observations into the existing DrawingEvidence contract without creating a second PlanModel or silently promoting candidates to architectural truth.

## Bug Hunt
- Reproduction: source identity, direct layer/block candidates, text, and dimensions are passed through the bridge.
- Root Cause target: prevent raw adapter payloads from bypassing the canonical evidence contract.
- Regression: source binding, missing SHA fail-closed, and no-PlanModel mutation are covered by unit tests.
- Required fail-closed states: UNKNOWN, NEEDS_REVIEW, BLOCKED remain available through the canonical reconciliation/evidence layer.
- PASS is not semantic truth; a supported evidence record is still only evidence.
- Exact-head verification is required before merge.
- false pass prevention: generic geometry is ignored by the bridge and cannot create architectural facts.
- Affected Contracts: drawing_semantic_evidence.py, evidence_reconciliation.py, dwg_semantic_evidence.py.
- Risk Classification: medium; this is an evidence-boundary adapter and must not become a semantic authority.
- Negative Tests: missing source SHA and generic geometry/no-PlanModel promotion are explicitly tested.
- Unresolved Findings: semantic Golden truth remains unresolved; real-world adversarial DWG fixtures remain pending.
- Final Decision: BLOCKED from semantic authority until reconciliation and Golden review provide sufficient evidence; safe to merge only as a normalization boundary after exact-head CI verification.
