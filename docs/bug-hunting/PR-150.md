# Bug Hunt — rejected execution audit status (PR 150)

## Scope
Correct the existing runtime audit defect where an invalid request can be recorded as `EXECUTE: PASS` before request validation. This change is limited to audit lifecycle correctness in the legacy runtime entrypoint and its regression tests.

## Bug Hunt
The first test-only commit adds a regression assertion before production code is changed. The required behavior is that rejected requests must never have a PASS execution event and must not report a complete/successful audit.

## Findings
- `runtime/app.py::execute` currently records `EXECUTE: PASS` before calling `validate_request`.
- Validation failures return immediately without recording a blocked/rejected audit outcome.
- The audit event can therefore claim success even though the request was rejected. This is a false-pass risk, not a cosmetic logging issue.
- The global audit trail and the current local execution identifier are also potential sources of cross-call event mixing; this PR's initial scope is restricted to the reproduced pre-validation PASS defect. Any additional correction must be supported by a separate failing regression test and remain within this audit-safety boundary.

## Reproduction
From the repository root, run:
`python -m unittest tests.test_runtime.RuntimeSliceTests.test_rejected_request_never_records_execute_pass -v`.
The test uses an explicit execution ID, submits a missing target, and inspects the real AuditTrail events for that execution.

## Root Cause
The execution lifecycle is recorded in the wrong order: an unconditional PASS event is written before validation and before the controlled-editing/approval gates. Early rejection paths do not overwrite that event with a fail-closed state.

## Regression
The regression test requires the rejected request to return REJECT, the last EXECUTE event to be BLOCKED, no PASS event to exist for that execution, and audit_complete/audit_ok to remain false. The test is committed before the production fix so CI can demonstrate the original defect.

## Required fail-closed states
Invalid or unsupported requests must remain REJECT/BLOCKED and must never create PASS audit evidence. UNKNOWN, NEEDS_REVIEW, and BLOCKED remain unresolved. An incomplete audit must not be promoted to PASS. No real CAD write or approval authority is introduced.
