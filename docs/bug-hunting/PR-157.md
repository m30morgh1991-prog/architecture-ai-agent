## Scope

Extend the existing read-only DXF comparator to compare XData and supported extension-dictionary records. This is metadata validation, not a new editing feature.

## Bug Hunt

The comparator previously ignored entity-attached XData and extension dictionary records. These can carry application-specific information that changes while visible geometry remains identical. Treating opaque or handle-dependent metadata as equivalent would create a false match.

## Findings

- XData is compared by application ID and normalized tag code/value pairs.
- Extension dictionaries are traversed with depth and entry limits.
- XRECORD tag payloads are compared.
- Binary tag values are represented by SHA-256 digests.
- Unresolved 1005 handle references and unsupported extension objects are marked ENTITY_METADATA_UNSUPPORTED.
- Metadata-only changes are reported separately and do not increase geometry mismatch counts.
- Opaque proxy entities remain unsupported; no proxy geometry is inferred.

## Reproduction

Run:
- `python -m unittest tests.test_dxf_comparator -v`

Synthetic fixtures isolate XData changes, XRECORD changes, and unresolved handle references. They verify metadata differences independently from model geometry and ensure unsupported references remain INCOMPLETE.

## Root Cause

Entity metadata is stored outside ordinary geometric DXF attributes. Ignoring these records can hide meaningful drawing changes; treating raw handles as stable identities can also create false differences across independently generated files.

## Regression

Permanent tests cover XData, extension dictionaries, XRECORD payloads, and unresolved handle references. Existing tests for geometry, styles, layers, blocks, nested INSERTs, layouts, viewports, UCS, extents, Persian text resilience and provenance remain required.

## Negative Tests
