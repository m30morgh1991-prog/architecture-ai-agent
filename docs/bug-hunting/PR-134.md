## Scope

PR #134 introduces an isolated DWG-to-DXF adapter around an installed ODA File Converter executable. It does not add a new DWG codec, alter the architectural reasoning core, or edit any source DWG.

## Bug Hunt

The adapter is intentionally conservative. It stages one copied source file in a private temporary directory, disables recursive discovery, invokes the executable without a shell, applies a bounded timeout, checks source SHA-256 before and after, and refuses to overwrite existing outputs. Its CLI arguments now follow ODA's documented order: source directory, target directory, input filter, output version/type, recursive flag, audit flag. Execution success is not conversion-fidelity PASS.

## Findings

- The adapter supports DWG to DXF only in v0.1.
- DXF-to-DWG is deferred until an independent DWG reopen and fidelity-verification path exists.
- The ODA executable is not bundled or downloaded by this repository. ODA's official FAQ states that non-members may use ODA File Converter only for non-commercial applications; the 2025 Community User Agreement also restricts commercial redistribution/use. A non-member deployment is evaluation-only and MUST NOT be used for commercial architecture-office workflows or shipped in a commercial product without separate written authorization or an appropriate commercial license.
- The output is marked fidelity UNKNOWN and requires review even when the converter exits successfully.
- The conversion-fidelity state is explicitly NEEDS_REVIEW until independent validation exists.
- A successful process exit must not create a false pass for fidelity, visual equivalence, or architectural correctness.
- The output-write failure path now removes a partial DXF only after this process has successfully created it. If exclusive creation fails because another process created the destination concurrently, that other process's file is preserved.
- The ODA CLI argument order was corrected against ODA's documented input order; a mocked regression asserts the filter precedes output version/type.
- No PlanModel, ConstraintMap, ApprovedChangePlan, semantic inference, or compliance authority is added.
- Golden DWG fixtures are not changed.
- Real Windows execution is NOT_RUN by explicit user constraint until Windows replacement and CAD software reinstallation.

## Reproduction

Run the Runtime Tests workflow or execute:
python -m unittest tests.test_oda_file_converter -v

For a real local conversion after an authorized ODA installation:
instantiate ODAFileConverter and call convert_dwg_to_dxf(source_path, output_path).
The original source directory is not passed to ODA; only a staged copy is exposed.

## Root Cause

The conversion codec is an external native application. This repository therefore separates orchestration and safety from codec implementation. A successful process exit and non-empty output cannot establish entity, layer, block, xref, dimension, text, layout, coordinate, unit, or scale fidelity.

A secondary filesystem race was identified in cleanup after an output-write error: blindly unlinking the destination could remove a path created by another process after the initial existence check. Cleanup is now guarded by a flag set only after this process successfully opens the destination with exclusive creation.

## Regression

Mocked tests cover success-path orchestration, source immutability, missing executable, non-zero exit, missing output, timeout, output collision, extension validation, configuration validation, staged-source hash mismatch, preservation of a concurrently-created destination when exclusive output creation fails, and the exact ODA CLI argument order. The tests do not execute ODA or establish real conversion fidelity.

## Required fail-closed states

Missing executable, timeout, non-zero exit, missing/ambiguous/empty output, source mutation, or output collision must be rejected. Fidelity remains NEEDS_REVIEW and UNKNOWN until independent comparison is implemented. No uncertain conversion may be promoted to PASS.

## CI Verification

PASS token is reserved for exact-head workflow evidence. The first exact-head Bug Hunt run found the missing required NEEDS_REVIEW and false pass evidence tokens; the subsequent documentation update addressed those validator findings. The safety-race and ODA CLI-order corrections require fresh exact-head PR CI Gate, Runtime Tests, and Mandatory Bug Hunt evidence. No real ODA conversion or Windows test has been run. Do not treat mocked adapter tests as codec fidelity evidence.

## Affected Contracts

- Source DWG remains immutable.
- Converted DXF is a derived artifact, not a replacement source of truth.
- Conversion adapter is optional and replaceable.
- PlanModel and ConstraintMap remain the canonical architectural understanding contracts.
- No cloud provider is required.

## Risk Classification

High risk if an output is treated as lossless or used for editing without independent fidelity evidence. Low risk for the isolated orchestration contract covered by mocked tests.

## Negative Tests

- Missing ODA executable must fail closed.
- Non-zero exit must fail closed.
- Timeout must fail closed.
- Missing, ambiguous, or empty output must fail closed.
- Existing output must never be overwritten.
- A destination created by another process during a failed exclusive-create attempt must remain untouched.
- Source hash change must reject the result.
- A staged input whose hash differs from the original source snapshot must be rejected before the external converter starts.
- Wrong input/output extensions must be rejected.
- A successful conversion must still retain fidelity NEEDS_REVIEW and UNKNOWN.

## Unresolved Findings

- Exact ODA File Converter installation path and command behavior on supported Windows hosts remain unverified.
- Real DWG-to-DXF fidelity on the two Golden fixtures remains unverified by this adapter.
- Independent DXF entity/layer/block/text/dimension/layout/coordinate/unit/scale comparison remains future work.
- DXF-to-DWG and cloud conversion adapters are not implemented.
- Commercial deployment is NOT_AUTHORIZED for non-members under ODA's published FAQ/Community User Agreement; an appropriate commercial license or written authorization is required before any office/product deployment.
- Official terms: https://www.opendesign.com/faq/question/what-are-oda-viewer-and-oda-file-converter and https://www.opendesign.com/files/2025-09/ODA%20Community%20User%20Agreement%2009-2025.pdf

## Final Decision

The v0.1 adapter is a bounded orchestration implementation only. Merge remains blocked until exact-head CI gates complete successfully and review accepts the scope. Even after CI success, this PR does not establish lossless CAD conversion or authorize production use of converted files without independent validation.


## Core Console research update

- AutoCAD Core Console is selected as the preferred local provider to qualify when a supported, licensed full AutoCAD installation is already available. It is not implemented or enabled in this PR.
- Autodesk documents Core Console script automation, and SAVEAS with FILEDIA=0, but the DXF prompt sequence is release-sensitive. A guessed script is not accepted as an implementation.
- The MIT acadbp repository demonstrates batch conversion through accoreconsole; this is useful prior art, not proof of our Golden DWG fidelity.
- DWG TrueView's similarly named executable is not assumed equivalent to full AutoCAD Core Console.
- A detailed version-specific qualification matrix is recorded in docs/architecture/AUTOCAD_CORE_CONSOLE_QUALIFICATION.md.
- Provider implementation and all real Windows/Core Console/Golden DWG tests remain NOT_RUN until the user confirms Windows replacement and CAD software reinstallation. This is an explicit hold, not a CI failure.
- No PlanModel, ConstraintMap, ApprovedChangePlan, or Golden DWG fixture was changed.


## Independent DXF validator update

- Added `runtime/cad_conversion/dxf_validator.py` using the separately declared ezdxf dependency.
- Validation is read-only and reports parse status, audit errors/fixes, entity type inventory, layers, blocks, layouts, dimensions, text counts, Persian-script presence counts, block-definition inventory, and INSUNITS/MEASUREMENT metadata.
- A parser/audit-clean DXF is only `PARSE_PASS`; fidelity remains `UNKNOWN` and review remains mandatory. This is not DWG-to-DXF fidelity evidence and does not replace source-vs-output comparison.
- Added synthetic DXF regression cases for valid structure, units, Persian MTEXT, block definitions, source immutability, missing/empty/wrong-extension/malformed files, and JSON serialization.
- The validator does not repair or save the input file. Real CAD/Golden-DWG validation remains NOT_RUN until the user's Windows and CAD installation is ready.


## Provider orchestration regression update

- Added the `CadConversionProvider` protocol, explicit `ProviderRegistry`, and `CadConversionEngine` facade.
- Provider registration and provider selection are explicit. No automatic provider discovery, fallback, or silent switch is permitted.
- The facade verifies source hash immutability, exact requested paths, output existence/non-empty state, output SHA-256, execution completion, and the mandatory v0.1 fidelity UNKNOWN/review contract.
- ODA implements the provider contract but is not automatically selected. AutoCAD Core Console remains unavailable until a version-qualified Windows implementation exists.
- Added synthetic tests for provider contract conformance, explicit selection, unavailable provider/no fallback, duplicate registration, source mutation, output hash mismatch, existing-output preservation, and rejection of false fidelity PASS.


## DXF comparison regression update

- Added read-only DXF-to-DXF comparison for supported entity geometry signatures, layout and block inventories, layers, layouts, INSUNITS, and MEASUREMENT.
- Supported signatures are limited to LINE, CIRCLE, ARC, POINT, LWPOLYLINE, TEXT, MTEXT, INSERT, and ELLIPSE. Unsupported entity types are reported and force `INCOMPLETE`; dimensions/hatches/splines/proxies are not certified by this comparator.
- Coordinate tolerance must be finite and positive. The report is JSON-serializable and neither input file is modified.
- Even a supported-content match remains fidelity UNKNOWN and requires review. This is a DXF-to-DXF comparator, not direct DWG parsing or proof of conversion fidelity.
- Added synthetic regression cases for identical drawings, geometry differences, unit differences, tolerance handling, unsupported dimensions, malformed candidates, JSON serialization, and read-only behavior.


## Expanded DXF comparison coverage (2026-11-13)

- Added a separate conservative fingerprint module for DIMENSION, HATCH, SPLINE, ATTRIB, ATTDEF and LEADER. Unsupported MLEADER remains INCOMPLETE.
