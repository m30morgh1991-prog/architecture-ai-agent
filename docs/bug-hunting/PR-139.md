# Bug Hunt — Open-source AEC/CAD research integration

## Scope

Documentation-only integration of selected upstream design patterns into the existing Architecture AI Agent boundaries. The PR adds an AutoCAD-MCP evaluation protocol, an optional IFC/BIM adapter contract, and mappings for plan-extraction and typed-revision concepts. No runtime implementation, dependency, dataset, Golden DWG, PlanModel schema, ConstraintMap, or ApprovedChangePlan behavior is changed.

## Bug Hunt

Review the complete six-file PR diff and verify that every adopted idea remains behind existing provider-neutral evidence and approval boundaries. The key failure modes are accidental promotion of external output to semantic truth, unsafe CAD writes, lossy IFC mapping, license contamination, and research claims being mistaken for tested product capability.

## Findings

- AutoCAD-MCP is documented as a candidate adapter implementation only. Upstream README claims have not been independently reproduced in this repository.
- The existing CAD adapter contract already enforces source binding, document/revision fencing, ApprovedChangePlan presence, postcondition revision and requested/actual operation equality. Existing tests cover these negative paths.
- The BIM-ready contract already supports optional IFC-style identity, properties, levels, parent references and typed relationships. It does not parse IFC files and must not be described as a completed IFC adapter.
- IfcOpenShell/IfcTester integration remains a future isolated, read-only pilot. No third-party package is added.
- plan-extract remains a research/demo comparator. No external dataset, model artifact or dependency is imported.
- Agent-CAD contributes design patterns only; no mechanical CAD runtime or worker is added.
- No H101 unlock, architecture rule approval, or production-readiness claim is made.
