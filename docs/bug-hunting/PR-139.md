# Bug Hunt — Open-source AEC/CAD research integration

## Scope

Documentation-only integration of selected upstream design patterns into the existing Architecture AI Agent boundaries. The PR adds an AutoCAD-MCP evaluation protocol, an optional IFC/BIM adapter contract, and mappings for plan-extraction and typed-revision concepts. No runtime implementation, dependency, dataset, Golden DWG, PlanModel schema, ConstraintMap, or ApprovedChangePlan behavior is changed.

## Bug Hunt

Review the complete six-file PR diff and verify that every adopted idea remains behind existing provider-neutral evidence and approval boundaries. The key failure modes are accidental promotion of external output to semantic truth, unsafe CAD writes, lossy IFC mapping, license contamination, and research claims being mistaken for tested product capability.

## Findings

- AutoCAD-MCP is documented as a candidate adapter implementation only. Upstream README claims have not been independently reproduced in this repository.
- The existing CAD adapter contract already enforces source binding, document/revision fencing, ApprovedChangePlan presence, postcondition revision and requested/actual operation equality. Existing tests cover these negative paths.
- The BIM-ready contract already supports optional IFC-style identity, properties, levels, parent references and typed relationships. It does not parse IFC files and must not be described as a completed IFC adapter.
- IfcOpenShell/IfcTester integration remains a future isolated, read-only pilot. No third-party package is added.
- plan-extract remains a research/demo comparator. No external dataset, model artifact or dependency is imported.
- Agent-CAD contributes design patterns only; no mechanical CAD runtime or worker is added.
- No H101 unlock, architecture rule approval, or production-readiness claim is made.

## Follow-up upstream research — 2026-11-15

A second source-checked pass expanded the research record with acadrust, CADCraft, OpenCADStudio, MLightCAD, and the dwgdxf wrapper. These are research-only additions; no runtime package, model, dataset, source code, or Golden fixture was imported.

- acadrust v0.6.8 is an MPL-2.0 pure-Rust native DWG/DXF read/write candidate. Its documented entity/version coverage and failsafe diagnostics justify an isolated conversion pilot, not production adoption.
- CADCraft uses acadrust through a DWG-to-DXF intermediate buffer. Its own parity notes identify untested real-file cases and lossy unsupported objects. A public issue reports high memory use on one large drawing; this is a bridge-path warning, not a measured result for direct acadrust APIs.
- OpenCADStudio is GPL-3.0 and remains an external reference only.
- MLightCAD's main viewer stack is MIT; its optional LibreDWG DWG worker is GPL-3.0 and has documented entity-coverage and memory limitations. It is only a possible future DXF-first read-only browser viewer.
- The dwgdxf wrapper has no asserted repository license and describes acadrust as MIT although the current acadrust repository declares MPL-2.0; it is not adopted pending clarification.

The research distinguishes upstream documentation and reported measurements from tests performed by this repository. No upstream compatibility, runtime, fidelity, license, or performance claim is counted as our own PASS. The isolated acadrust pilot must pin the dependency, audit third-party notices, compare exact input/output hashes and entity inventories, measure memory/time, preserve unsupported/recovered records as unresolved, and remain outside PlanModel / ConstraintMap / ApprovedChangePlan. Golden DWG and Windows/AutoCAD host execution remain read-only / NOT_RUN as applicable.
