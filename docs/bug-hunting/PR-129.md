# Bug Hunt — PR #129 AIE architecture and Autodesk read-only adapter

## Scope
Introduces the AIE v0.1 architecture baseline, read-only core facade, and the first Autodesk AutoCAD evidence adapter. The adapter consists of a host-side AutoCAD .NET 8 plug-in source and a Python evidence-envelope validator. It does not edit drawings, create a second semantic model, promote architectural semantics, or assess compliance. BIM expansion remains deferred.

## Bug Hunt
The Autodesk implementation is split at the host boundary. Generic CI can validate the Python evidence contract but cannot compile or execute the C# plug-in without an installed AutoCAD host and its managed assemblies. The C# build and host smoke test are pending. The plug-in requires a named, unmodified active document and uses read-only database access. It exports a separate JSON file only.

- Load with NETLOAD, run AIEEXPORTREADONLY, and export evidence from a disposable DWG copy.
- Run python -m unittest tests.test_autodesk_dwg_evidence_adapter -v.
- Confirm source SHA-256 before and after extraction is identical.

## Root Cause / Risk
AutoCAD's managed API is version- and host-specific. Generic cloud CI cannot prove the plug-in compiles or executes against AutoCAD. Matching disk hashes also do not independently prove that the active in-memory database equals the disk bytes; this limitation is preserved as NEEDS_REVIEW.

## Regression
- Preserve existing DWG evidence extractors, CAD contracts, Golden manifests, and Golden source bytes.
- Never use OpenMode.ForWrite, save the source document, or export over the source path.
- Never upgrade INSUNITS to proof of drawing scale.
- Keep semantic authority and compliance assessment false.
- Unsupported entities, nested blocks, xrefs, proxy objects, and dimension associations remain unresolved.
- Source SHA mismatch, malformed envelope, or authority-boundary violation is BLOCKED.
- UNKNOWN, NEEDS_REVIEW, and BLOCKED never become PASS without evidence.
- Any new commit invalidates previous exact-head CI results.

## Required fail-closed states
- Missing source/export, malformed JSON, schema mismatch, missing entity identity, hash mismatch, or read-only invariant failure -> BLOCKED.
- Unitless/unknown units or unverified active-database snapshot identity -> NEEDS_REVIEW.
- No status grants permission to edit or declares semantic correctness.
