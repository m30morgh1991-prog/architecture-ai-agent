# Bug Hunt — PR #129 AIE architecture and Autodesk read-only adapter

## Scope
Introduces the AIE v0.1 architecture baseline, read-only core facade, and the first Autodesk AutoCAD evidence adapter. The adapter consists of a host-side AutoCAD .NET plug-in and a Python evidence-envelope validator. It does not edit drawings, create a second semantic model, promote architectural semantics, or assess compliance. BIM expansion remains deferred.

## Bug Hunt
The Autodesk implementation is split at the host boundary. Generic CI can validate the Python evidence contract but cannot compile or execute the C# plug-in without an installed AutoCAD host and its managed assemblies. The C# build and host smoke test are deliberately NOT_RUN until the user reinstalls Windows and required software. The plug-in requires a named, unmodified active document and uses read-only database access. It exports a separate JSON file only.

## Findings
- PR: https://github.com/m30morgh1991-prog/architecture-ai-agent/pull/129
- Existing DWG semantic extractor and CAD read-only contracts are reused; no duplicate semantic authority is introduced.
- Autodesk API access is an in-process AutoCAD .NET plug-in, not the Autodesk Product Help connector or a mandatory cloud API.
- Host runtime target and managed-assembly compatibility still require validation on the user's installed AutoCAD version.
- Level-text parsing binds values to FFL/RL/EL/T.O./Persian elevation markers; `LEVEL 2` alone and uncontextualized numbers do not become elevations.
- Snapshot binding review finding fixed: the Python validator now ignores the exporter's self-asserted `snapshot_binding_status=VERIFIED` field and always returns NEEDS_REVIEW. Matching disk hashes prove disk-file continuity only; they do not independently prove identity of the active in-memory AutoCAD Database. This closes the identified false pass path.
- PR #127 geometry-export overlap resolved in this branch: direct parser-native coordinates for supported LINE/LWPOLYLINE/ARC/CIRCLE/ELLIPSE/SPLINE entities are retained with coordinate-frame status UNKNOWN, no semantic authority, and entity-specific CSV fields. OCS/WCS and INSERT transform reconciliation remain unresolved.
- Dimension evidence review finding partially addressed: AlignedDimension exports WCS XLine1Point, XLine2Point, and DimLinePoint. Other Dimension subtypes are explicitly marked unsupported/NEEDS_REVIEW. Exporting definition points is not dimension-to-geometry reconciliation and does not validate measured geometry.

## Reproduction
- Run `python -m unittest tests.test_autodesk_dwg_evidence_adapter -v` in repository CI.
- The regression suite includes a forged `snapshot_binding_status=VERIFIED` envelope and asserts NEEDS_REVIEW.
- When Windows is reinstalled, build against the installed AutoCAD managed assemblies, NETLOAD, and export from a disposable DWG copy. This host test is currently NOT_RUN.
- Confirm source SHA-256 before and after extraction is identical.

## Root Cause
The Golden evidence artifact exposed a layer-extraction defect in the existing ezdwg path: it looked for an entity-level layer name, while ezdwg exposes a layer handle on each entity and a separate Document layer table. The corrected extractor resolves entity layer handles through that table. The Golden rerun supports direct WALL and COULMN (source spelling) layer-name candidates, while DOORS and WINDOWS remain UNKNOWN. INSUNITS=1 is recorded as inches metadata, but scale remains NEEDS_REVIEW because no independent scale/dimension correspondence has been established. Matching disk hashes or successful CAD extraction are not proof of architectural meaning or byte-identical active database state.

## Risk
AutoCAD's managed API is version- and host-specific. Generic cloud CI cannot prove the plug-in compiles or executes against AutoCAD. Matching disk hashes do not independently prove that the active in-memory database equals disk bytes. Aligned-dimension definition points are exported as evidence only; no dimension-to-geometry reconciliation is performed.

## Regression
- Preserve existing DWG evidence extractors, CAD contracts, Golden manifests, and Golden source bytes.
- Prefer an elevation-marker-attached value over a floor index; `LEVEL 2` alone must not produce elevation evidence.
- Multiple plausible elevation values in one label must produce UNKNOWN with no numeric elevation.
- Never use OpenMode.ForWrite, save the source document, or export over the source path.
- Never upgrade INSUNITS to proof of drawing scale.
- Keep semantic authority and compliance assessment false.
- A forged VERIFIED snapshot-binding claim must remain NEEDS_REVIEW.
- AlignedDimension must export three WCS definition points; unsupported Dimension subtypes remain explicitly NEEDS_REVIEW.
- Dimension geometry reconciliation remains NOT_PERFORMED.
- Unsupported entities, nested blocks, xrefs, proxy objects, non-aligned dimension subtype points, OCS/WCS reconciliation, and INSERT transforms remain unresolved.
- Source SHA mismatch, malformed envelope, or authority-boundary violation is BLOCKED.
- Malformed PlanModel element collections must return a BLOCKED inspection result without crashing during result formatting.
- UNKNOWN, NEEDS_REVIEW, and BLOCKED never become PASS without evidence.
- Any new commit invalidates previous exact-head CI results.

## Required fail-closed states
- Missing source/export, malformed JSON, schema mismatch, missing entity identity, hash mismatch, or read-only invariant failure -> BLOCKED.
- Unitless/unknown units or unverified active-database snapshot identity -> NEEDS_REVIEW.
- Unsupported dimension subtype -> NEEDS_REVIEW.
- No status grants permission to edit or declares semantic correctness.
