# Bug Hunt — PR #121 Read-only Golden DWG evidence export

## Scope
Adds a bounded read-only evidence export script and manual/pull-request workflow. No source Golden DWG is edited, resaved, normalized, or replaced.

## Bug Hunt
The purpose is to avoid waiting for binary attachments by exporting the existing DWG parser's evidence from GitHub Actions. This is evidence collection only, not semantic authority or a regulatory compliance verdict. Missing or inconsistent source evidence must not create a false pass.

## Findings
- PR: https://github.com/m30morgh1991-prog/architecture-ai-agent/pull/121
- Initial head: `7484e01e5385f10af057b0631c3150a4768602ce`
- Exporter checks the manifest SHA-256 before extraction and rechecks it after extraction.
- JSON retains source evidence, dimension entities, text labels, layer/block inventories, units metadata, and header bounds where exposed by the existing parser.
- CSV outputs are review aids; dimension rows are marked NEEDS_REVIEW and are not automatically compared against code.
- Exact-head CI and workflow artifact remain pending until workflows complete.

## Reproduction
Run `python -m runtime.export_golden_dwg_evidence` from the repository root after installing `requirements.txt`. The workflow `.github/workflows/golden-dwg-evidence-export.yml` runs this command and uploads `artifacts/golden-dwg-evidence/` as a short-retention artifact.

## Root Cause
GitHub's text-file fetch connector cannot return binary DWG content to the chat session. The repository's existing runtime dependency and tests already demonstrate a supported in-CI extraction route; the missing part was a durable export artifact for review.

## Regression
- Preserve the two Golden DWG files byte-for-byte.
- Fail closed if either source is missing or the manifest SHA-256 does not match.
- Fail closed if the source hash changes during extraction or differs from the extractor's reported hash.
- Keep semantic authority false and regulatory compliance unassessed.
- No H101 or stage advancement is authorized by the export itself.

## Required fail-closed states
Hash mismatch, missing source, parser exception, or incomplete extraction blocks the export. Ambiguous units, dimension text, view association, or regulatory applicability remain UNKNOWN / SOURCE_REQUIRED / NEEDS_REVIEW, never PASS.

## CI Verification
The initial PR head has not yet been accepted as Green. PR CI Gate, Runtime Tests, Mandatory Bug Hunt, and the evidence-export workflow must be completed/success on the same exact-head commit before merge. A generated artifact proves extraction ran; it does not prove compliance.

## Negative Tests
- A missing Golden file must block.
- A wrong source hash must block before export.
- A source hash changed during extraction must block.
- An extractor/source hash disagreement must block.
- Empty dimension/text lists must be represented as empty extraction results, not as proof that no dimensions or labels exist.
- The exporter must not modify source files; source_mutated is reported false only after before/after hash equality.
- Missing evidence must never produce a false pass.
