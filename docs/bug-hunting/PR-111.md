# Bug Hunt — preserve BLOCKED for hard Golden runner failures (PR #111)

## Scope
Fix a fail-closed decision downgrade in the H100 Golden Understanding runner when a source is missing, its SHA-256 differs from the manifest, or the understanding execution raises an exception.

## Reproduction
`runtime/golden_understanding_runner.py::_case_report` previously returned only the generic evaluator's decision. The runner's hard-failure paths set the observed decision to `BLOCKED` and add an `extra_failures` entry, but generic domain/expected-decision mismatches could make the final report say `NEEDS_REVIEW`. The existing exception test encoded this downgrade as expected behavior.

## Root Cause
The report aggregator did not preserve the hard-failure state from the source/execution boundary; it treated these failures like ordinary semantic domain mismatches.

## Fix
- If `extra_failures` is non-empty, the report decision is now `BLOCKED`.
- Updated the exception regression test to require `BLOCKED`.
- Added negative tests for missing source and SHA-256 mismatch.
- Kept the generic semantic evaluator's behavior unchanged for non-hard-failure observations.

## Fail-Closed / Regression
Hard source/execution failures must remain `BLOCKED`; they cannot be downgraded to `NEEDS_REVIEW` or promoted to `PASS`. Golden DWG assets are not modified. H100 remains active and H101 remains locked.
