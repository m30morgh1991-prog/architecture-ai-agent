# Bug Hunt — preserve BLOCKED for hard Golden runner failures (PR #111)

## Bug Hunt
Fix a fail-closed decision downgrade in H100 Golden Understanding reports for missing source files, source SHA-256 mismatches, and understanding execution exceptions.

## Scope
Ensure hard source/execution failures remain BLOCKED in the final report; add regression coverage for all three hard-failure paths.

## Findings
The runner recorded `BLOCKED` in observations and added `extra_failures`, but the final report exposed the generic evaluator decision. Domain/expected-decision mismatches could downgrade a hard failure to `NEEDS_REVIEW`. The old exception test encoded that downgrade.

## Reproduction
In `runtime/golden_understanding_runner.py::_case_report`, observe a missing source, a manifest SHA-256 mismatch, or an exception from `PlanUnderstandingCore.understand`. The observed fail-closed decision is BLOCKED but the prior final report could be NEEDS_REVIEW.

## Root Cause
The report aggregator discarded the source/execution boundary's hard-failure status and treated it like an ordinary semantic domain mismatch.

## Regression
Added negative tests requiring BLOCKED for missing source and SHA-256 mismatch, and changed the exception regression test to require BLOCKED. The generic semantic evaluator remains unchanged for non-hard-failure observations.

## Required fail-closed states
UNKNOWN, NEEDS_REVIEW, and BLOCKED must never be promoted to PASS. A missing source, source hash mismatch, or execution exception is BLOCKED. A false pass is prohibited even when the generic evaluator reports only a domain mismatch.
