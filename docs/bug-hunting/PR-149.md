# Bug Hunt — acadrust DWG-to-DXF isolated pilot (PR 149)

## Scope
Add an isolated Rust experiment under tools/acadrust_dwg2dxf_pilot using exact acadrust version 0.6.8. No production dependency, architectural model contract, Golden input, or production conversion path is changed.

## Bug Hunt
Review focuses on unsafe success claims, input mutation, unbounded parser allocations, incomplete output validation, overwriting user files, and accidental adoption as a production backend.

## Findings
- acadrust is invoked in strict mode with failsafe recovery disabled and a 512 MiB decompressed-data cap plus mesh caps.
- The probe hashes the original DWG before and after processing and never opens it for writing.
- DXF output is streamed from CadDocument to a same-directory temporary file; it is reopened by acadrust and then inspected independently by ezdxf.
- Existing candidate/report paths are never overwritten.
- Structural mismatches, skipped/recovered records, diagnostics, or omitted architecture records produce BLOCKED.
- Even when all structural checks match, the decision remains NEEDS_REVIEW. No fidelity PASS is possible in this pilot.
- The current execution environment has no Rust/Cargo installation, so local compilation is NOT_RUN; GitHub Actions is the authoritative compilation/test environment.

## Reproduction
From repository root, generate Cargo.lock, run cargo fmt and cargo test for tools/acadrust_dwg2dxf_pilot, then run the converter against each immutable Golden DWG and pass its candidate/report to verify_ezdxf.py. The PR workflow performs these steps and uploads reports and candidate files.

## Root Cause
The previous DWG-to-DXF experiment relied on a path whose Golden conversion lost most entities. A separate, isolated direct-document-to-writer pilot is needed to determine whether a Rust implementation can preserve the project fixtures without requiring AutoCAD, while keeping production conversion blocked until independent evidence exists.

## Regression
Three Rust tests cover synthetic DWG conversion, malformed DWG rejection without output, and refusal to overwrite an existing candidate. The workflow also checks formatting, dependency lock generation, strict compilation, Golden conversion, and independent ezdxf reopening. Golden fixtures remain read-only.

## Required fail-closed states
UNKNOWN, NEEDS_REVIEW, and BLOCKED are valid unresolved outcomes. Parser success, a zero exit code, or matching aggregate counts are not a fidelity PASS. No output is promoted into production; only a named candidate artifact is produced. Windows/AutoCAD host tests remain NOT_RUN.

## Affected Contracts
Only the isolated conversion experiment, its report schema, and its dedicated CI workflow are affected. PlanModel, ConstraintMap, ApprovedChangePlan, BIM understanding, GeometryReference/H101, Golden DWG fixtures, and production CAD provider selection are unchanged.

## Risk Classification
Moderate experimental risk because native CAD parsing/writing can omit or reinterpret records. Runtime production risk remains isolated by the separate tool directory, exact dependency pin, no production manifest change, no overwrite behavior, and explicit NEEDS_REVIEW/BLOCKED states. MPL-2.0 compliance must be reviewed before distribution.

## Negative Tests
- Malformed DWG input must not create a candidate or report.
- Existing candidate output must remain byte-for-byte unchanged.
- Input SHA-256 before/after must match.
- Nonzero skipped/recovered records or parser diagnostics must block.
- Entity/table/unit/version mismatches must block.
- Independent ezdxf parse failure or core inventory mismatch must block.
- No false pass from parser success or aggregate entity count alone.
- No production dependency, automatic PR merge, or CAD host claim is introduced.

## Unresolved Findings
- Rust/Cargo compilation and tests await GitHub Actions.
- Golden fixture conversion and independent ezdxf comparison are pending.
- Per-entity properties, dimensions, XData, proxy graphics, nested blocks, layouts, fonts, OCS/WCS, and native AutoCAD/ODA compatibility are not yet comprehensively compared.
- Windows/AutoCAD host tests remain NOT_RUN.
- Cargo.lock checksum must be committed/pinned before any production adoption; current workflow generates and uploads the lockfile as pilot evidence.
- MPL-2.0 distribution obligations require a separate compliance review.
- No production provider selection or H-stage advancement is authorized.

## Final Decision
This PR is a draft research pilot only. It cannot be merged as a production feature, cannot authorize CAD editing, and cannot promote conversion fidelity to PASS. Merge still requires explicit owner authorization for this PR and its exact head SHA.
