# Bug Hunt — PR-74 AutoCAD-MCP adapter boundary

## Scope
Add a provider-neutral CAD adapter contract and integration boundary for AutoCAD-MCP without connecting live AutoCAD or enabling uncontrolled writes.

## Bug Hunt
Check source binding, document fencing, idempotency, ApprovedChangePlan enforcement, postcondition readback, requested-vs-actual diff, headless compatibility, and fail-closed behavior.

## Findings
The existing Architecture Core already has source-bound drawing evidence and reconciliation. A separate provider-neutral CAD adapter seam is required so AutoCAD-MCP can be used without becoming a second semantic model.

## Reproduction
Run:
python -m unittest tests/test_cad_adapter_contract.py -v
python -m unittest tests/test_bug_hunting_gate.py -v
Then inspect the contract and verify that invalid source hashes, missing approval, missing postconditions, and mismatched actual operations are rejected.

## Root Cause
Before this change there was no explicit typed boundary for an external CAD execution adapter, making direct integration risk bypassing PlanModel, evidence reconciliation, and ApprovedChangePlan controls.

## Regression
The adapter contract is intentionally dependency-free. It does not import AutoCAD-MCP, AutoCAD, COM, LISP, or ezdxf. It therefore cannot silently activate live CAD execution. Unsupported or unverifiable execution remains BLOCKED or NEEDS_REVIEW.

## CI Verification
Exact-head PR CI, Runtime Tests, and Bug Hunt must all pass. No live AutoCAD PASS is claimed by this PR.

## Final Decision
BLOCKED until exact-head CI is green. No false pass is permitted; this PR establishes only the safe adapter boundary and deterministic contract tests.
