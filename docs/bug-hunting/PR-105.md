# Bug Hunt — scheduled governance health check (PR #105)

## Bug Hunt

## Scope
Add an unattended, read-only scheduled workflow that checks mainline health while the ChatGPT app is closed. The workflow must not edit repository files, merge pull requests, or unlock project stages.

## Findings
- Existing PR CI, Runtime Tests, and Mandatory Bug Hunt workflows run on repository events; this addition provides a scheduled/manual mainline health check.
- GitHub Actions runs independently of the user's tablet or ChatGPT app.
- The new workflow checks out `main`, runs runtime smoke tests, the unittest suite, and Bug Hunt governance contract tests, then writes a summary.
- Exact-head PR checks and required H100 regressions remain authoritative for accepting project changes.

## Reproduction
- Inspect `.github/workflows/scheduled-governance-health-check.yml`.
- Trigger the workflow manually after it is available on the default branch, or wait for the scheduled run.
- Inspect the workflow summary and confirm that it reports the exact checked-out main SHA and the final job result.
- Confirm that a failed/cancelled step cannot be described as Green.

## Root Cause
Closing ChatGPT stops this chat's active work; existing event-triggered CI does not itself provide a scheduled health report. A separate GitHub-hosted workflow is needed for unattended verification. This workflow is intentionally not an autonomous code-editing agent.

## Regression
- Regression requirement: scheduled and workflow_dispatch triggers are present.
- Regression requirement: workflow permissions remain read-only (`contents: read`).
- Regression requirement: runtime smoke tests, unittest suite, and Bug Hunt governance contract tests are all run.
- Regression requirement: failed/cancelled health checks report BLOCKED, never PASS.
- Regression requirement: no automatic commits, PR merges, or H-stage unlocks occur.
- Regression requirement: Golden DWG assets are not changed.

## Required fail-closed states
- BLOCKED until all exact-head CI gates for this PR complete successfully.
- UNKNOWN / NEEDS_REVIEW evidence must never be promoted to PASS.
- A successful scheduled health run is not proof that H100 semantic Golden acceptance is complete.
- H100 remains active; H101 remains LOCKED.
- This workflow is read-only and must not bypass review, Green Gate, Bug Hunt, or regression requirements.
- This is a false pass prevention requirement, not permission to bypass governance.

## Risk Classification
Low-to-medium: this is a read-only CI workflow, but schedule and test commands affect unattended compute usage. No application runtime contract, repository state file, PR state, or Golden DWG asset is changed.

## Negative Tests
- Governance contract tests must reject missing headings and missing evidence tokens.
- Verify the health summary states BLOCKED when a required step fails or is cancelled.
- Verify workflow permissions do not allow contents writes.
- Verify no Golden DWG file changes are included in the diff.
- Verify no automatic merge, file edit, or H-stage transition is implemented.

## Unresolved Findings
- This workflow provides unattended verification only; it does not autonomously diagnose and fix code or create implementation PRs.
- A true AI coding runner requires an explicitly selected execution/provider path and secured credentials; no provider secret is assumed or introduced here.
- The first scheduled run cannot occur until this workflow is merged into the default branch.
- Exact-head CI and post-merge mainline checks remain to be observed; absent or pending results are not Green.
- H100 semantic Golden ground truth and real-world transformed/defective fixtures remain incomplete; H101 remains LOCKED.

## Final Decision
BLOCKED until exact-head PR CI, Runtime Tests, and Mandatory Bug Hunt complete successfully and the scheduled workflow's post-merge manual run is verified. PASS is permitted only on completed/success evidence; no false pass is acceptable.
