## Scope

This PR hardens the existing read-only DXF reader, validator and comparator. It does not introduce a standalone text-processing feature. The goal is to keep valid geometry and drawing structure readable when Persian text is legacy-shaped, reversed, unreadable, or references an unavailable SHX font.

## Bug Hunt

The reader previously treated several entity-level access paths as trusted. A text decode/signature exception could escape the narrow exception handling in entity collection, and strict parser failure ended reading before a recovery attempt. The new behavior isolates per-entity text failures, tries ezdxf recovery after strict parse failure, and marks recovered or text-incomplete comparisons as incomplete rather than claiming full content equivalence.

Missing SHX is normally a style dependency, not a reason for ezdxf to stop reading geometry. No SHX file is loaded, substituted, or repaired by this change.

## Findings

- Missing SHX references and Persian text in synthetic DXFs are accepted by the reader without changing source files.
- Injected text extraction/signature exceptions are isolated from LINE geometry extraction.
- Unreadable text is represented as TEXT_READ_UNAVAILABLE; overall comparison remains INCOMPLETE while independently supported geometry can remain MATCHED.
- Recovery use is explicitly represented as DXF_RECOVERY_USED and prevents a full supported-content match.
- Fidelity remains UNKNOWN and human review remains required.
- No automatic RTL reversal, Unicode normalization, KATEB emulation, text repair, or font substitution is performed.

## Reproduction

Run:
- `python -m unittest tests.test_dxf_validator -v`
- `python -m unittest tests.test_dxf_comparator -v`

The synthetic tests create DXFs with missing SHX style references, reversed/legacy-shaped Persian strings, and injected text extraction failures. They assert that LINE geometry remains available and that uncertainty is not promoted to PASS.

## Root Cause

Text/style data and geometric entities share the same DXF document, but they do not have the same authority or failure impact. Treating every text access as a prerequisite for processing the document risks discarding independent geometry. The parser and audit phases also need a conservative recovery boundary for damaged records.

## Regression

Permanent regression tests cover missing SHX references, Persian text that is deliberately not normalized, isolated validator text-read failures, and comparator text-signature failures. Existing tests for malformed DXF, geometry, blocks, dimensions, layers, units, provenance, and read-only source preservation remain in force.

## Required fail-closed states

- Any recovered document is incomplete and remains subject to review.
- Text read failure is UNKNOWN/NEEDS_REVIEW; it is not silently trusted.
- Unsupported geometry remains INCOMPLETE.
- Fidelity remains UNKNOWN.
- Missing evidence remains BLOCKED.
- No uncertain state may be promoted to PASS.
- No false pass is allowed.

## CI Verification

The PR CI Gate, Runtime Tests, and Mandatory Bug Hunt must each report completed/success on the exact-head SHA after the final commit. Pending, missing, failed, or stale-SHA evidence is BLOCKED. A prior green run is not evidence for a later head. CI PASS does not prove DWG-to-DXF fidelity or printed Persian text correctness.

## Affected Contracts

Only CAD conversion DXF reading, validation, comparison, and their tests are affected. PlanModel, ConstraintMap, ApprovedChangePlan, BIM understanding, architectural interpretation, and provider selection contracts are unchanged. The source DXF/DWG remains read-only.

## Risk Classification

Moderate. Recovery behavior can expose partial records, so recovered input is always marked incomplete. Entity-level exception isolation must not suppress errors in supported geometry. Synthetic CI tests are required before merge. Real Windows, AutoCAD, ODA and Golden DWG checks remain NOT_RUN until the user confirms the Windows environment is ready.

## Negative Tests

- Missing source, empty source and malformed non-DXF input still fail closed.
- Missing SHX must not crash parsing or erase independent LINE geometry.
- Reversed Persian text must not be modified.
- Injected text extraction/signature exceptions must not abort geometry extraction.
- A recovered DXF must not be reported as MATCHED_SUPPORTED_CONTENT.
- Source files must remain byte-identical.
- Unknown text or geometry must never be promoted to PASS.

## Unresolved Findings

- Actual Windows/AutoCAD/ODA behavior with the user's installed SHX and KATEB environment remains NOT_RUN.
- Plot/PDF output direction and font rendering cannot be certified by DXF parsing alone.
- Broader malformed/truncated/resource-exhaustion fixtures remain outstanding.
- Additional layouts, viewports, UCS/WCS, XData, extension dictionaries and proxy-object coverage remains outstanding.
- The current PR does not repair or normalize text; any correction remains with the originating CAD author.

## Final Decision

This is a narrow resilience fix within the existing CAD reader/comparator. Do not merge until Bug Hunt, PR CI Gate, Runtime Tests, exact-head verification and review are all complete. No merge is requested by this evidence file. PASS applies only to the tested software gates, never to unverified drawing fidelity. No false pass is allowed.
