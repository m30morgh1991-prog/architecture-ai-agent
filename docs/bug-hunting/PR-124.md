# Bug Hunt — PR #124 fenced-code heading validation regression

## Scope
Isolated ECC-inspired TDD pilot for a governance defect in the Bug Hunt evidence validator. The current change adds a minimal parser fix and regression tests. No PlanModel, ConstraintMap, ApprovedChangePlan, BIM, architectural understanding, or Golden DWG assets are changed.

## Bug Hunt
The original validator used substring checks across the complete Markdown file. A required heading inside a fenced code example could therefore be counted as a real section, producing a false pass. The defect was reproduced by the test-only RED phase.

- The branch now includes the minimal fix and regression tests for headings and required tokens inside fenced code.

## Reproduction
Run `python -m unittest tests.test_bug_hunting_gate`. The heading test removes the real `## Regression` heading and places it only inside a fenced block; it expects `MISSING_SECTION:## Regression`. The token test ensures a required token occurring only inside a fenced block is rejected.

## Root Cause
Confirmed root cause: `validate_evidence` originally checked required headings with substring membership over the full document. Fenced code content was incorrectly treated as evidence. The fix checks exact Markdown heading lines and required tokens only outside fenced code blocks. An unclosed fence fails closed by excluding the remaining content.

## Regression
The permanent regression tests verify that fenced-code headings and tokens cannot satisfy the evidence schema. Genuine required headings and tokens must continue to pass, while missing required evidence must remain blocked. UNKNOWN, NEEDS_REVIEW, and BLOCKED must never be promoted to PASS without evidence.

## Required fail-closed states
Confirmed defect; minimal fix implemented. Missing, queued, in-progress, failed, or mismatched-SHA checks remain UNKNOWN/BLOCKED, never PASS. NEEDS_REVIEW remains required whenever evidence is incomplete or ambiguous.
