# Bug Hunt — PR #124 fenced-code heading validation regression

## Scope
Test-only TDD RED phase for the Bug Hunt evidence validator. The change adds a regression test requiring a Markdown section heading inside a fenced code block not to satisfy the corresponding required section. No implementation, PlanModel, ConstraintMap, ApprovedChangePlan, BIM, architectural understanding, or Golden DWG files are changed.

## Bug Hunt
The validator currently checks required section headings using substring membership against the complete evidence text. The new test removes the real `## Regression` heading and includes that heading only inside a fenced code block. Under the current implementation, the code-block text is still a substring, so the test is expected to expose a false pass. This expected RED status must be confirmed by the actual CI result before describing it as reproduced.

## Root Cause
Confirmed root cause: `validate_evidence` used substring membership over the entire Markdown document, so `## Regression` inside a fenced code block satisfied the section check. The RED test reproduced the false pass. The fix now validates section headings and required tokens only against lines outside fenced code blocks.
