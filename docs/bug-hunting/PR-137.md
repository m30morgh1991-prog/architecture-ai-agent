# Bug Hunt Evidence — PR 137 Space Geometry Numeric Validation

## Scope

Harden SpaceModel input and validation against invalid numeric geometry. The change does not alter topology algorithms, units, coordinate frames, architectural semantics, or editing permissions.

## Bug Hunt

SpaceRecord previously checked bounding-box ordering and positive area using ordinary comparisons. NaN values can pass those comparisons because comparisons with NaN are false. Python booleans are also numeric subtypes and float(True) silently converts to 1.0. Invalid geometry could therefore enter the spatial model and contaminate downstream area/topology calculations.

## Findings

- Bounding-box coordinates, centroid coordinates, and area must all be finite numeric values.
- Boolean values must not be interpreted as numeric coordinates or areas.
- Infinity and NaN must be rejected before any geometry comparison or topology analysis.
- Valid geometry remains unchanged.
- This validation does not prove units, scale, coordinate frame, or architectural meaning.
- No false pass is allowed for malformed numeric geometry.

## Reproduction

Pass a space record with bbox [0, 0, NaN, 10], centroid [5, Infinity], area NaN, or bbox coordinate True to build_space_model. The previous builder converted values with float() and SpaceRecord.validate used only x1 <= x0, y1 <= y0, and area <= 0. NaN could bypass those comparisons, and True became 1.0.

## Root Cause

The geometry contract lacked finite-number validation and used permissive float coercion. Numeric ordering checks alone do not reject NaN or Infinity, and bool is accepted by Python's float conversion.

## Regression

Added tests verify:
- NaN in bounding-box coordinates is rejected;
- Infinity in centroid coordinates is rejected;
- NaN area is rejected;
- boolean coordinates are rejected;
- boolean area is rejected;
- existing valid space geometry and unknown semantic statuses remain valid.

## Required fail-closed states

- UNKNOWN: architectural meaning, units, or coordinate frame are not established.
- NEEDS_REVIEW: downstream unit/scale/coordinate interpretation remains incomplete.
- BLOCKED: NaN, Infinity, boolean, or non-numeric geometry is rejected.
- PASS: never inferred from numeric validity alone.

## Risk Classification

Medium geometry-integrity risk. Non-finite or coerced boolean values can corrupt bounding-box ordering, centroid, area and topology calculations, even when the detector otherwise remains fail-closed.

## Negative Tests

The regression suite explicitly proves that invalid numeric values cannot be silently accepted. Boolean values cannot become 1.0 or 0.0. Numeric validity alone cannot promote an architectural space or relation to PASS.

## Unresolved Findings

- SpaceModel still needs explicit validated unit, coordinate-frame and scale provenance before metric area/dimension claims can be trusted.
- The current SpaceModel source identifier length validation is weaker than other canonical contracts and should be reviewed separately.
- Windows/AutoCAD host verification remains NOT_RUN pending the user's Windows reinstall and software setup.
