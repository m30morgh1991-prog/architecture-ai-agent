# Bug Hunt — independent runner safety contract (PR #108)

## Scope
Add a deterministic policy contract and tests for the future unattended AI runner. This PR does not implement provider calls or autonomous code execution.

## Bug Hunt
Review found a fail-open gap: the original contract checked only SHA/stage syntax. A stale but well-formed SHA or a syntactically valid but non-authoritative stage could otherwise pass those checks. This was fixed by requiring independently observed current-main SHA and authoritative active-stage values and blocking any mismatch.

## Findings
- The policy contract remains deterministic and side-effect-free.
- Only explicit success for all required gates permits isolated task work.
- Current-main SHA must match the proposed main SHA; stale SHA blocks.
- The proposed stage must match the authoritative persisted active-stage ID.
- The contract never authorizes merge or H-stage advancement.
- Missing provider configuration blocks AI execution.

## Reproduction
Run python -m unittest tests/test_independent_runner_policy.py -v and python -m unittest discover -s tests -p 'test_*.py' -v on the exact PR head.

## Root Cause
An unattended runner needs a machine-checkable boundary so missing, stale, conflicting, or incomplete state cannot be mistaken for permission to implement or advance the project.

## Regression
Regression tests assert stale SHA, missing authoritative state, non-authoritative stage, pending/missing/failed/cancelled/skipped/unknown gates, absent provider configuration, invalid SHA/stage, and an unresolved/unknown agent PR are blocked. Tests also assert can_merge=false and can_advance_stage=false.

## Required fail-closed states
UNKNOWN, NEEDS_REVIEW, and BLOCKED must never be promoted to PASS. Missing provider configuration, invalid or stale SHA, invalid or non-authoritative stage, incomplete gates, or an unresolved agent PR blocks task execution. A false pass is prohibited.

## CI Verification
The earlier PR #106 head passed its gates, but this replacement PR is based on current main and requires fresh PR CI, Runtime Tests, Mandatory Bug Hunt, and policy tests before merge. Until those checks complete successfully, the final decision is BLOCKED.

Medium: this is a governance authorization contract. It is currently not wired to execute external commands, call a model, change repository files, merge PRs, or unlock stages.

## Negative Tests
Negative tests explicitly cover stale SHA and non-authoritative stage ID as well as invalid/missing SHA, missing authoritative state, absent gate snapshot, pending gates, missing provider configuration, unknown PR state, and an existing agent PR. They assert can_merge=false and can_advance_stage=false.

- The new policy module is a deterministic contract only; wiring it into a least-privilege runner is future work.
- Repository ruleset Min currently requires zero approving reviews; human review enforcement remains a separate governance improvement.
- H100 remains active and H101 remains locked.
