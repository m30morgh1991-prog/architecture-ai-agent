# Bug Hunt — PlanElement evidence promotion guard (PR 162)

## Scope

Harden the canonical PlanModel contract against direct-construction bypasses that could assign LOCKED or EDITABLE state without adequate source-bound evidence. This PR is stacked on PR #136 and changes validation only.

## Bug Hunt

Review focused on false promotion from boolean confidence, invalid state strings, UNKNOWN/UNCERTAIN/CONTRADICTED evidence, and confidence inflation beyond the referenced evidence.

## Findings

- Python bool is a numeric subtype; `True` must not be accepted as confidence 1.0.
- PlanElement state must be restricted to LOCKED, EDITABLE, CONDITIONAL, or UNKNOWN.
- Existing PlanModel validation checks evidence ID existence and type matching, but did not require supported evidence for LOCKED/EDITABLE promotion.
- Existing validation did not prevent PlanElement confidence from exceeding the strongest referenced evidence confidence.
- A PlanModel without an evidence bundle remains a legacy compatibility form; it must not be accepted as the authoritative production execution snapshot.
- No false pass is allowed.

## Reproduction

Construct PlanElement directly with confidence=True or an unsupported state string. Separately, construct a PlanModel with a source-matching evidence bundle whose referenced evidence is UNKNOWN, then assign the PlanElement state LOCKED. Finally, construct SUPPORTED evidence with confidence 0.80 and a LOCKED PlanElement with confidence 0.99. Before the fix, these direct constructions could pass the relevant element/model checks.

## Root Cause

Validation was split between the reconstruction builder and PlanModel. The reconstruction builder guarded candidate confidence, but direct PlanElement construction bypassed that check. PlanModel verified evidence references and type identity but did not check whether the referenced evidence was strong enough to justify LOCKED/EDITABLE state.

## Regression

Added negative tests verify:
- Boolean, NaN, Infinity, and numeric-string PlanElement confidence are rejected.
- Unknown PlanElement state strings are rejected.
- UNKNOWN evidence cannot promote an element to LOCKED.
- PlanElement confidence cannot exceed the strongest referenced SUPPORTED evidence.
- Existing type-mismatch and constraint-state overlap tests remain in place.

## Required fail-closed states

- UNKNOWN: evidence is missing or unresolved; no promotion.
- NEEDS_REVIEW: evidence is incomplete or conditional.
- BLOCKED: invalid state, malformed confidence, unsupported promotion evidence, or confidence inflation.
- PASS: not emitted from unsupported evidence.
- LOCKED/EDITABLE: only permitted when the evidence bundle is source-bound, type-matched, SUPPORTED, and strong enough for the declared confidence.

## Negative Tests

- NaN/Infinity/numeric strings cannot be accepted as confidence.
- Unknown state values cannot enter PlanModel.
- UNKNOWN evidence cannot justify LOCKED.
- Evidence confidence 0.80 cannot justify PlanElement confidence 0.99.
- No PlanModel without evidence bundle is promoted by this patch.
- No real CAD write or Windows host behavior is changed.
