# Bug Hunt Evidence — PR 189 IDEM-01 Unknown Completion Shapes Fail Closed

## Scope

IDEM-01: an idempotency result must be recognized as completed only when it carries an explicitly supported terminal state or status. Unknown or malformed shapes must not be assumed complete.

## Bug Hunt

Review focused on the `IdempotencyGuard.has_completed()` decision boundary and the distinction between a missing key, a running workflow, an explicit terminal result, and an unknown/malformed result object.

## Findings

The previous implementation returned `True` when a stored result had neither a recognized `state` nor a recognized dict `status`. It also attempted set membership for malformed non-string values, which could raise TypeError instead of returning a fail-closed decision.

## Reproduction

Test-first regressions store an arbitrary object, an empty dict, an unknown status, and unhashable list-valued state/status fields. Before the fix, arbitrary objects and empty dicts were reported completed, while list-valued fields could raise TypeError. After the fix, all these cases return False.

## Root Cause

The previous fallback treated the absence of recognized lifecycle evidence as proof of completion. It also assumed state/status values were hashable strings without validating their types.

## Regression

- Only explicit terminal states SUCCEEDED, FAILED, and BLOCKED are accepted from a state field.
- Only explicit terminal statuses PASS, REJECT, NEEDS_REVISION, SUCCEEDED, FAILED, and BLOCKED are accepted from a status field.
- Unknown objects, empty dictionaries, missing lifecycle fields, unknown labels, and malformed non-string values return False.
- RUNNING and UNKNOWN workflow states remain incomplete.
- Request fingerprint conflicts remain unchanged and continue raising IDEMPOTENCY_KEY_REUSED_WITH_DIFFERENT_REQUEST.

## Affected Contracts

- `runtime/idempotency.py` — explicit terminal-state/status recognition and fail-closed fallback.
- `tests/test_idempotency.py` — unknown and malformed result-shape regressions.

## Risk Classification

Moderate: completion detection controls replay/lifecycle behavior. The change is conservative and may cause previously accepted but undocumented result shapes to be treated as incomplete; callers must provide an explicit supported terminal status/state.

## Required fail-closed states

UNKNOWN, RUNNING, NEEDS_REVIEW, malformed, and unrecognized result shapes remain incomplete and never become PASS or completed by inference. This prevents a false pass.

## Negative Tests

- Unknown object does not count as completed.
- Empty dict does not count as completed.
- Unknown status does not count as completed.
- Unhashable state/status does not raise and does not count as completed.
- Existing terminal states and statuses remain recognized.
- Different request fingerprints continue to conflict.

- This PR does not change in-flight reservation atomicity, key storage concurrency, persistence, expiry, or workflow payload fingerprinting.
- Independent security review and full integration after PR #180 remain required.
