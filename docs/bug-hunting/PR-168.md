# Bug Hunt Evidence — PR 168 Advisory Space-Program Fit Diagnostics

## Scope

Add a deterministic advisory analysis over the existing source-bound SpaceModel. The first slice checks architect-supplied room-area targets/ranges, required and unwanted adjacency, and explicitly evidenced accessible-opening paths. It does not generate or edit geometry and does not perform legal/code compliance checks.

## Reproduction

Construct a SpaceModel with explicitly identified spaces and evaluate it against a SpaceProgramRequirement. Cases with an area below the supplied minimum, an explicitly disconnected required adjacency, or an unwanted shared boundary should produce traceable findings. Cases with missing adjacency/opening evidence must remain review findings, not be misreported as proven defects.

## Root Cause

The existing SpaceModel represents spaces and relations, but there was no dedicated deterministic contract to compare that existing model with an architect-authored room program and return explainable, evidence-linked design feedback. Without a separate analysis layer, area and adjacency observations would otherwise be mixed into detection or treated as approval/compliance decisions.

## Findings

- Added `runtime/design_quality_analysis.py` as an advisory-only analysis layer.
- Inputs are explicit SpaceModel IDs and architect-authored requirements; no inferred room-name matching.
- Area deviations are INFO/WARNING suggestions, not hard failures.
- Required adjacency is considered established only by explicit SHARED_BOUNDARY or CONNECTED_BY_OPENING evidence.
- Missing relation evidence produces REQUIRED_ADJACENCY_UNRESOLVED.
- Circulation paths count only explicitly ACCESSIBLE CONNECTED_BY_OPENING relations.
- Missing path evidence produces REVIEW; it is not proof that no route exists.
- Each finding carries source evidence IDs, affected space IDs, an explanation and a design-oriented suggestion.
- No aggregate quality score is emitted because it could imply a false precision or ranking without validated weights and complete inputs.

## Affected Contracts

- `runtime/space_model_contract.py` — consumed and validated; not modified.
- `runtime/design_quality_analysis.py` — new advisory analysis contract.
- `tests/test_design_quality_analysis.py` — new deterministic tests.
- `runtime/plan_model_contract.py` — not modified.
- `runtime/impact_analysis.py` — not modified.
- `runtime/app.py` — not modified; analysis is not yet wired into HTTP/runtime execution.

## Risk Classification

Medium design-interpretation risk. Area values inherit the units and coordinate assumptions of the supplied SpaceModel. The analysis does not independently establish units, scale, room boundary correctness, daylight, ventilation, privacy, furniture fit or code compliance. The architect remains responsible for interpreting suggestions.

## Regression

Tests cover:
- area below minimum and deviation from target;
- explicit accessible-opening path traversal;
- missing path evidence remains NEEDS_REVIEW;
- explicit disconnected required adjacency;
- missing topology evidence does not become a false adjacency claim;
- unwanted adjacency warning;
- invalid area ranges;
- boolean area rejection.

## Negative Tests

The tests prove that:
- boolean area values cannot be coerced into numbers;
- bounding-box proximity alone does not establish adjacency;
- absence of an opening path in incomplete evidence is not described as proof that no path exists;
- an advisory finding does not become an automatic edit or approval decision.

## Required fail-closed semantics

- UNKNOWN / NEEDS_REVIEW: evidence is incomplete or a relationship cannot be established.
- BLOCKED: malformed source/model contracts are rejected by the existing SpaceModel validation boundary.
- PASS: this module does not emit a compliance PASS or architectural approval. A finding-free result is named ANALYSIS_COMPLETE and means only that the supplied checks found no discrepancy.
- False pass: no missing evidence, unknown relation or unprovided requirement can be silently treated as satisfied.

## Unresolved Findings

- The analysis is not yet connected to a user-facing design-review workflow.
- Metric area claims require validated source units, scale and coordinate frame.
- More detailed functional quality measures (daylight, ventilation, privacy, circulation width, furniture clearance and ergonomics) need explicit inputs and validated evidence before implementation.
- Space boundaries and opening semantics still depend on upstream detection quality.
- No Golden DWG semantic truth is claimed by these synthetic contract tests.
- No real CAD write, permit decision, regulatory assessment or automatic design change is enabled.
