# Bug Hunt Evidence — PR 136 Empty Detector Evidence Contract

## Scope

Fix the canonical PlanModel reconstruction path when the detector returns no candidates for required architectural element types. Add a static external-repository research note. No new semantic model or runtime dependency is introduced.

## Bug Hunt

The detector may correctly return zero candidates and list fixed element types as unresolved. Reconstruction previously created an empty ElementEvidenceBundle. PlanUnderstandingCore then had no evidence IDs for ConstraintMap, while ConstraintMap.validate requires at least one evidence reference. This produced an exception instead of a valid UNKNOWN result.

## Findings

- Empty detector output is a legitimate fail-closed outcome, not an exceptional condition.
- Candidate confidence and bounding boxes must be finite numeric values; booleans must not be coerced to 1.0 or 0.0.
- An unresolved element type must remain visible in the evidence bundle and ConstraintMap.
- A detector-gap record is explicitly UNKNOWN, kind UNKNOWN, confidence 0.0, source-hash-bound, and states that absence of detection is not evidence of absence.
- No detector gap can become LOCKED, EDITABLE, PASS, or editing permission.
- No false pass is permitted.

## Reproduction

Call build_plan_model_from_detection with a valid source SHA, an empty candidates list, and unresolved_fixed_element_types containing the required fixed element types. Then call PlanUnderstandingCore. Previously, the reconstruction bundle contained no evidence items, so PlanUnderstandingCore passed an empty evidence_ids tuple into ConstraintMap and ConstraintMap.validate raised MISSING_CONSTRAINT_EVIDENCE.

## Root Cause

The reconstruction contract only generated ElementEvidence from detected candidates. It represented unresolved types in unresolved_element_types, but did not generate a traceable UNKNOWN evidence reference for a type with no candidate. The downstream ConstraintMap contract requires evidence_ids, so the empty result could not be composed.

## Regression

New tests cover:
- empty candidates with all fixed element types unresolved;
- deterministic source-bound UNKNOWN evidence records;
- confidence 0.0 and kind UNKNOWN for detector-gap records;
- PlanModel reconstruction validation;
- PlanUnderstandingCore composition with zero detected elements;
- explicit UNKNOWN type buckets and non-empty ConstraintMap evidence references;
- boolean, NaN, infinity, out-of-range confidence, and malformed/non-finite bounding boxes.

## Required fail-closed states

- UNKNOWN: no candidate was emitted; this does not prove the element is absent.
- NEEDS_REVIEW: downstream review is still required for incomplete evidence.
- BLOCKED: invalid source or malformed contracts remain blocking.
- PASS: not emitted by the empty detector path.
- LOCKED: never emitted from synthetic detector-gap evidence.

## Risk Classification

Medium contract-integrity risk. An empty evidence list can crash the understanding pipeline precisely when the detector is uncertain. The patch preserves uncertainty while allowing a structured fail-closed result.

## Negative Tests

Tests prove that missing detection does not produce a PlanElement, does not produce a LOCKED state, and does not imply architectural absence. The generated evidence is UNKNOWN with zero confidence. No false pass, semantic promotion, or editing permission is introduced.

## Unresolved Findings

- The detector itself still needs better recall for columns, outer boundaries, walls, doors, and windows.
- SpaceModel still needs explicit validated unit, coordinate-frame and scale provenance before metric area/dimension claims can be trusted.
- IFC parsing remains a future optional read-only adapter.
- External models and datasets in the research note have not been runtime tested or adopted.
- Windows/AutoCAD host verification remains NOT_RUN pending the user's Windows reinstall and software setup.

## Final Decision

Implementation candidate only. Candidate confidence and bounding-box validation were hardened against boolean coercion, non-finite values, out-of-range confidence, and malformed extents. The latest code/test/evidence commits require fresh exact-head PR CI, Runtime Tests and Bug Hunt success; no earlier-head result is carried forward.
