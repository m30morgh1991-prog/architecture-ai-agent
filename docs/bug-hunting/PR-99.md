# Bug Hunt — H100 Golden Scale/Unit Bridge

## Bug Hunt

## Scope
Expose source-bound native DWG unit metadata in the Golden Understanding report without treating unit declaration as verified drawing scale.

## Findings
The scale/unit contract existed independently, while the Golden Understanding report always emitted dimensions as UNKNOWN and did not expose a scale/unit observation derived from the detector's DWG metadata.

## Reproduction
Run `python -m unittest discover -s tests -p "test_dwg_scale_unit_bridge.py" -v` and `python -m unittest discover -s tests -p "test_golden_understanding_runner.py" -v`.

## Root Cause
The DWG detector already returned the native `dwg_units` metadata field, but the Golden report did not pass that field into the scale/unit contract. The first integrated test run then exposed two test-contract mismatches: blocked observations represent scale/unit as the scalar `UNKNOWN`, and the Golden source-hash test assumed every expected domain must be UNKNOWN even after adding a review-only scale-unit candidate.

## Required fail-closed states
- Recognized unit metadata alone is NEEDS_REVIEW, never PASS.
- Missing, unitless, malformed, or unsupported metadata remains UNKNOWN.
- Existing dimension interpretation remains UNKNOWN until dimension-to-geometry evidence is independently verified.

## Regression
A narrow bridge maps only recognized DXF `$INSUNITS` values: 1=inches, 2=feet, 4=millimetres, 5=centimetres, 6=metres. Unitless, unsupported, missing, string-typed, or boolean values remain UNKNOWN. Recognized metadata alone is NEEDS_REVIEW because it does not prove a scale ratio or dimension-to-geometry correspondence.

## CI Verification
Intermediate exact-head PR CI and Runtime runs failed on the two test-contract mismatches above. The implementation and tests were corrected to accept scalar `UNKNOWN` for blocked observations and to permit only `UNKNOWN` or `NEEDS_REVIEW` for the scale-unit domain; all other semantic domains remain expected `UNKNOWN`. These fixes require a fresh exact-head PR CI, Runtime Tests, and Mandatory Bug Hunt run. Do not merge until all are completed/success on the same final head.

## Affected Contracts
`runtime/dwg_scale_unit_bridge.py`, `runtime/golden_understanding_runner.py`, `runtime/scale_unit_evidence.py`, `tests/test_dwg_scale_unit_bridge.py`, and `tests/test_golden_understanding_runner.py`.

## Risk Classification
Medium. Misreading unit metadata as a verified scale can corrupt dimensional interpretation. The bridge deliberately does not promote dimensions or scale to PASS.

## Negative Tests
- Recognized unit metadata remains NEEDS_REVIEW without independent scale/dimension evidence.
- Unitless, unsupported, missing, string-typed, and boolean metadata remain UNKNOWN.
- Golden report still emits UNKNOWN when the observation is blocked or detector output has no unit metadata.
- Golden manifest allows only UNKNOWN/NEEDS_REVIEW for scale_unit and keeps every other unresolved domain UNKNOWN.
- Existing dimensions remain UNKNOWN; no semantic dimension truth is fabricated.

## Unresolved Findings
The bridge does not yet extract explicit scale ratios, validate dimension-to-geometry associations, reconcile unit labels in text/title blocks, or establish cross-view scale consistency. Those require separate source-bound evidence and Golden regression.

## Final Decision
BLOCKED until exact-head PR CI, Runtime Tests, and Mandatory Bug Hunt are all green and applicable review requirements are satisfied.

PASS is not allowed from unit metadata alone.
false pass prevention: scale/unit ambiguity remains unresolved.
exact-head verification is mandatory.
