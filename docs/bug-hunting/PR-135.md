# Bug Hunt Evidence — PR 135 Opening Host-Wall Evidence Guard

## Scope

Harden the existing opening-to-space connectivity helper. This change does not add a second PlanModel, replace SpaceModel, authorize editing, or promote any relation to approval-grade semantics.

## Bug Hunt

The existing connectivity helper accepted a non-empty host_wall_id as corroboration when host_wall_ids was omitted or empty. This allowed an unverified identifier to act like a verified wall reference. The success path also indexed span_evidence_id and host_wall_evidence_id without first validating their presence, allowing incomplete input to raise KeyError instead of returning a fail-closed result.

## Findings

- Host-wall identity must be checked against an explicitly supplied inventory.
- Missing or empty host-wall inventory cannot verify a host wall.
- The opening, span, host-wall, and both space evidence references must be present before a connected relation candidate is emitted.
- Two distinct space endpoints are required.
- A structurally corroborated relation remains UNKNOWN until downstream semantic review.
- The patch does not claim a false pass and does not alter edit authorization.

## Reproduction

Call classify_opening_connectivity with two adjacent space boundaries, a native opening span, and a non-empty host_wall_id, but omit host_wall_ids. The previous implementation treated the host wall as evidenced and emitted CONNECTED_BY_OPENING. Removing host_wall_evidence_id or span_evidence_id from an otherwise qualifying opening could also raise KeyError.

## Root Cause

The prior boolean condition used `not host_wall_ids or host_wall_id in host_wall_ids`, so an absent or empty inventory bypassed the membership check. The success path assumed optional evidence keys existed instead of validating the complete evidence contract before indexing them.

## Regression

Added tests cover:
- absent and empty host-wall inventories;
- host-wall IDs not present in the supplied inventory;
- missing host-wall and span evidence IDs;
- missing space evidence;
- duplicate space IDs;
- missing opening IDs;
- successful evidence reconciliation remaining UNKNOWN.

## Required fail-closed states

- UNKNOWN: missing, incomplete, or unverified connectivity evidence.
- NEEDS_REVIEW: downstream state for incomplete or ambiguous evidence.
- BLOCKED: invalid or contradictory evidence at the consuming contract boundary.
- PASS: not emitted by this helper; it never authorizes connectivity or editing.

## Risk Classification

Medium safety risk: false room-to-room connectivity can corrupt downstream accessibility, circulation, and spatial validation. The guard reduces false-positive connectivity but does not establish architectural correctness.

## Negative Tests

The regression suite explicitly verifies that missing or mismatched host-wall inventory cannot produce CONNECTED_BY_OPENING. Missing evidence IDs cannot be silently accepted. A successful structural candidate remains UNKNOWN, preventing false pass and unsafe promotion.

## Unresolved Findings

- Native host-wall association still depends on the upstream adapter supplying a trustworthy host-wall inventory and source-bound evidence IDs.
- Geometric tolerance and wall/opening interpretation require validation against real CAD drawings and architecture-specific golden cases.
- Windows/AutoCAD runtime verification remains NOT_RUN pending the user's Windows reinstall and software setup.

## Final Decision

Implementation candidate only. Merge remains blocked until exact-head CI, Runtime, Bug Hunt, and required human review are complete.
