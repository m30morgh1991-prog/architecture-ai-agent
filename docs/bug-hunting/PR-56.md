# H96: release gate evidence hardening

## Scope
H96 closes a fail-open release gate where truthy caller values could satisfy readiness without explicit evidence.

## Bug Hunt
### reproduction
The previous release gate normalized values with bool(), so strings such as PASS could become a successful check. It also had no checks for audit, idempotency, or real runtime evidence.

### root cause
The gate consumed asserted booleans instead of strict evidence signals and did not include the lifecycle controls added in H93-H95.

### regression
The gate now requires explicit True for every required evidence category: contracts, workflow, final validation, regression, semantic corroboration, audit, idempotency, and runtime. UNKNOWN, NEEDS_REVIEW, BLOCKED, missing evidence, and unresolved state remain fail-closed.

## Findings
- Non-boolean truthy values cannot produce PASS.
- Missing audit/idempotency/runtime evidence blocks release.
- The release gate grants no authority; it only evaluates readiness.

## Regression
Permanent tests cover complete evidence, missing evidence, truthy non-boolean input, and fail-closed states.

## CI Verification
Bug Hunt Gate, PR CI Gate, Runtime Tests, and regression must all be successful. No missing or UNKNOWN CI result is treated as green.

## Final Decision
Merge only after all required gates are genuinely green and post-merge main CI is observable.
