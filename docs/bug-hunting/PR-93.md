# Bug Hunt — H100 DWG Section Marker Evidence

## Bug Hunt

## Scope
Add conservative source-bound evidence extraction for explicit section/cut-plane/elevation/detail marker text and named marker blocks. Do not infer arrow direction, cut-plane geometry, or architectural meaning from an isolated label.

## Findings
Only contextual text such as «مقطع A-A» / “SECTION A-A”, or a block name explicitly identifying a section/cut-plane/elevation/detail marker, is recorded as a supported marker candidate. A bare “A-A” remains unpromoted. Direction and cut-plane status remain UNKNOWN.

## Reproduction
Run \`python -m unittest tests/test_dwg_semantic_evidence.py -v\`.

## Root Cause
The read-only DWG evidence extractor captured text and block names but did not expose explicit section-marker candidates as a typed, source-bound evidence domain.

## Regression
New tests cover Persian section context, a bare A-A negative case, and an explicit marker block. Marker evidence retains the input source SHA-256 and DIRECT provenance.

## Required fail-closed states
A PASS may apply only to detecting an explicitly supported marker candidate; it must never apply to direction, cut-plane geometry, or authoritative architectural meaning without separate evidence.
UNKNOWN, NEEDS_REVIEW, and BLOCKED remain valid. Marker presence does not establish section direction, cut-plane endpoints, view geometry, or semantic authority.

## CI Verification
Do not merge until PR CI Gate, Runtime Tests, and Bug Hunt Gate are completed/success on the exact final head. Required Golden regression must remain intact.

## Affected Contracts
\`runtime/dwg_semantic_evidence.py\`, \`tests/test_dwg_semantic_evidence.py\`, and the read-only DWG evidence schema. No PlanModel, ConstraintMap, or canonical relation graph is replaced.

## Risk Classification
Medium. A false section direction or cut-plane could corrupt cross-view coordination; this change intentionally leaves those fields UNKNOWN.

## Negative Tests
- Bare “A-A” does not produce a marker.
- Arrow glyph in marker text does not promote direction.
- Marker existence does not promote cut-plane geometry.
- The output remains read-only and \`semantic_authority=false\`.

## Unresolved Findings
Geometric cut-plane extraction, arrow-head/direction geometry, cross-view section reconciliation, scale/unit evidence, Iranian drafting convention coverage, and real-world adversarial Golden fixtures remain pending.

## Final Decision
BLOCKED until exact-head PR CI, Runtime Tests, and Bug Hunt Gate are all green.
