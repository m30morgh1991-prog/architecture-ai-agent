## Scope

Implement an HTTPS-only, loopback-only runtime listener with explicit TLS material and bearer authentication for read-only execution-record retrieval. Keep the legacy execution POST route blocked before request-body consumption. This PR is stacked on PR #173 and is not independently mergeable.

## Bug Hunt

Review the transport boundary, startup failure behavior, TLS context configuration, bearer-token parsing, authentication header ambiguity, loopback binding, and preservation of the canonical-execution fail-closed boundary.

## Findings

- Runtime startup now requires certificate and private-key paths plus a bearer token of at least 32 UTF-8 bytes.
- The listener wraps its socket in a TLS server context with TLS 1.2 minimum and binds only to 127.0.0.1:8443.
- No plaintext HTTP listener, redirect, or HTTP fallback is created.
- Read-only execution-record lookup requires exactly one valid Bearer Authorization header; duplicate or missing headers are rejected.
- POST /v1/execute remains HTTP 503 / BLOCKED before the request body is read.
- No canonical execution registry, CAD write capability, or remote binding is introduced.

## Reproduction

Run the focused tests in `tests/test_https_transport_security.py`, `tests/test_http_request_guardrails.py`, and `tests/test_http_canonical_execution_fail_closed.py`, followed by the full unittest suite.

## Root Cause

The previous runtime created a plaintext HTTP listener on loopback and had no transport-level TLS setup or authentication for execution-record reads. A documentation-only HTTPS contract did not implement the transport boundary.

## Regression

- Missing TLS certificate or key configuration prevents startup.
- Missing or weak bearer token prevents startup.
- TLS server context is configured with TLS 1.2 minimum and wraps the listener socket.
- Listener remains loopback-only on port 8443.
- Missing, duplicate, and invalid bearer credentials are rejected.
- Valid bearer credentials permit read-only record lookup.
- Legacy execution POST remains BLOCKED before reading untrusted body bytes.
- No HTTP fallback or remote/LAN listener is introduced.

## Required fail-closed states

UNKNOWN, SOURCE_REQUIRED, NEEDS_REVIEW, ABSTAIN, and BLOCKED are never promoted to PASS. Missing TLS material or authentication configuration prevents startup. Missing live handshake evidence remains NOT_RUN.

## Risk Classification

High security significance. The transport listener is now TLS-wrapped and authenticated for read-only lookups, but automated tests do not prove a live TLS handshake or client-side certificate verification. Remote access remains disabled. Execution remains blocked.

## Negative Tests

- Missing TLS configuration cannot start the server.
- Missing/weak API token cannot start the server.
- Duplicate Authorization headers cannot authenticate.
- No bearer token cannot read execution records.
- Forged client-provided EDITABLE state cannot reach the HTTP execution handler.
- No plaintext HTTP listener or fallback is created.
