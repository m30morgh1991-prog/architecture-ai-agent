## Scope

Extend the existing read-only DXF comparator to compare layout table properties, paper-space viewport parameters, named UCS records, drawing extents/limits, and coordinate-system header variables. This completes planned coverage in Issue #141 and does not add a new architectural capability.

## Bug Hunt

The comparator previously compared layout names and unit headers but did not compare the actual layout record settings, viewport camera state, named UCS axes/origins, or extents/coordinate metadata. A drawing could therefore differ in how its paper-space view is presented or how its coordinate system is interpreted while those differences remained unreported.

## Findings

- Layout record attributes are normalized and compared while volatile handles/owners are excluded.
- VIEWPORT parameters are compared as structural/presentation metadata, not counted as model geometry.
- Named UCS records include their origin and axis definitions.
- Per-layout geometric extents are computed from readable non-text/non-viewport entities; layout limits are compared through layout records. Raw `$EXTMIN/$EXTMAX` header values are not trusted because ezdxf may reset stale extents on read.
- UCS, insertion base, tile mode, worldview and related header values are compared independently.
- Geometry mismatch counts exclude viewport and text differences; fidelity remains UNKNOWN and review remains required.

## Reproduction

Run:
- `python -m unittest tests.test_dxf_comparator -v`

Synthetic fixtures isolate layout tab order, viewport view height, named UCS origin, header extents and UCS header changes. They assert the corresponding structural difference and ensure metadata-only changes do not become model-geometry mismatches.

## Root Cause

The comparator's previous structural inventory was incomplete. Layout names and unit values alone do not capture the page setup identity, viewport configuration, named coordinate frames, or drawing extents used by downstream CAD consumers.

## Regression

Permanent tests now cover each missing category independently. Existing tests for geometry, blocks, dimensions, layers, units, text resilience, malformed input, provenance, and read-only input preservation remain required.

## Risk Classification

Moderate. Incorrect normalization of viewport or coordinate metadata could create false differences or hide real ones. All values are normalized deterministically using the configured tolerance; handles and ownership references are excluded. Tests must verify both detection and geometry-status separation. Windows, AutoCAD, ODA and Golden DWG tests remain NOT_RUN until the user confirms the Windows environment is ready.

## Negative Tests

- Changing a layout tab order/limit is detected as layout metadata, not geometry.
- Changing viewport camera height is detected as a viewport difference, not a model geometry mismatch.
- Changing a named UCS origin/axis is detected.
- Changing header extents is detected.
- Changing UCS/INSBASE header variables is detected.
- Unchanged input files remain byte-identical.
- No metadata-only change can promote fidelity to PASS.

## Unresolved Findings

- Text/viewport geometry is excluded from computed geometric extents; those are compared through their own content paths.
- Plot-device/page setup data, CTB/STB dependencies and actual PDF plot equivalence still need separate evidence.
- Full viewport clipping and frozen-layer semantics require additional fixtures.
- External references, XData, extension dictionaries, proxy objects and resource-exhaustion tests remain outstanding.
- Real Windows/AutoCAD/ODA and Golden DWG execution remain NOT_RUN.
