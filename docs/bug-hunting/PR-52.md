# H92 Final Validation Bypass Guard — Bug Hunt

## Scope
Remove the legacy final-validation PASS path that could bypass the H91 fail-closed contract.

## Bug Hunt
Reproduction: call the legacy dictionary API with only `locked_delta_ids=[]` and `unauthorized_delta_ids=[]`.
Root cause: `runtime/final_validation.py` returned PASS from two shallow booleans without source/model identity, approved scope, before/after evidence, post-edit validation, or audit completeness.
Finding: the H91 contract existed but the legacy adapter did not route through it.
Fix: the legacy API now delegates to the H91 contract and returns UNKNOWN whenever required evidence is missing; malformed complete evidence is BLOCKED.

## Findings
The old minimal-input PASS was a real fail-open defect.
UNKNOWN, NEEDS_REVIEW, and BLOCKED never become PASS.
The adapter does not grant edit authority.
Unresolved or missing evidence is explicitly fail-closed and cannot be promoted to PASS.

## Regression
Added a permanent regression for the exact legacy minimal-input reproduction.
Added coverage for clean H91 evidence, blocked deltas, missing model identity, and UNKNOWN before/after evidence.
Bug Hunt initially exposed contract drift in five legacy E2E/runtime tests: they still expected the pre-H91 REJECT/PASS result vocabulary.
Root cause of the CI failure was stale test expectations, not a fail-open implementation defect.
Migrated the affected fixtures to the H91/H92 status model: complete evidence can PASS; blocked evidence returns BLOCKED; incomplete evidence returns UNKNOWN; release remains blocked.
The migrated tests preserve the original security assertions and make the contract change explicit.

## CI Verification
Exact-head CI must be re-run after the regression migration.
Required before merge: exact-head Bug Hunt, Runtime Tests, and PR CI. Mainline verification remains separate after merge.

## Final Decision
Merge only if the legacy bypass is eliminated, regression coverage passes, and exact-head CI is successful.
