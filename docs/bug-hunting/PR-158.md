## Scope

Add an inventory-only path for ACAD_PROXY_ENTITY proxy graphics and ACAD_PROXY_OBJECT counts. Opaque proxy data is never interpreted as authoritative geometry.

## Bug Hunt

Proxy entities can contain graphics data that is useful for provenance and change detection but cannot safely be treated as fully understood geometry. Previously these entities were simply marked unsupported, without a stable fingerprint of their opaque graphics. Proxy objects in the OBJECTS section also lacked an explicit count in the comparison report.

## Findings

- ACAD_PROXY_ENTITY proxy graphic bytes are hashed with SHA-256 and reported with byte count and available class/drawing-format metadata.
- Proxy graphic inventory changes are detected independently from model geometry mismatch counts.
- ACAD_PROXY_OBJECT instances are counted in the object section.
- Proxy entities remain in the unsupported entity inventory; matching graphics do not make the comparison complete.
- Opaque graphics are not exploded, decoded into geometry, or treated as fidelity proof.

## Reproduction

Run:
- `python -m unittest tests.test_dxf_comparator -v`

Synthetic proxy entities use opaque byte payloads. Tests verify that changed proxy bytes are detected, identical bytes remain INCOMPLETE, and geometry status is never promoted to MATCHED for drawings containing unsupported proxy entities.

## Root Cause

A proxy graphic is a visual representation supplied by another application, not a complete semantic entity definition. Comparing only entity type loses useful change evidence; interpreting the graphic as native geometry would overstate certainty.

## Regression

Permanent tests cover changed and identical proxy graphics. Existing tests for XData, extension dictionaries, styles, layers, blocks, layouts, viewports, UCS, extents, Persian text resilience and supported geometry remain required.
