# Bug Hunt Evidence — PR 173 Runtime Audit Fail-Closed Preservation

## Scope
Carry the rejected-execution audit correction into the current fail-closed HTTP runtime branch without reopening HTTP execution.

## Bug Hunt
The current HTTP route correctly returns HTTP 503 / BLOCKED before reading an untrusted request body. However, the local `execute()` function still recorded `EXECUTE: PASS` before request validation. A rejected local execution could therefore leave a false PASS audit event.

## Findings
The HTTP adapter remains safely blocked, but the local execution function had retained the false-PASS audit defect. The patch separates these boundaries: HTTP stays BLOCKED and local rejected executions no longer record PASS. It also carries forward request-payload fingerprinting for idempotency, nested dataclass response serialization, the local request-schema validator, and PR-ref-aware Bug Hunt evidence lookup. The request validator is tested directly; the HTTP route itself remains blocked before parsing.

## Reproduction
Call `execute()` with a valid PlanModel and a ChangeRequest targeting a missing element, while supplying a unique execution ID. Inspect the corresponding audit events.

## Root Cause
The runtime execution function inherited the pre-PR-150 behavior. The HTTP containment patch blocked the network adapter but did not carry forward the independent audit-state correction.

## Regression
- `EXECUTE: STARTED` is recorded before validation.
- Validation rejection records `EXECUTE: BLOCKED`.
- Controlled-editing and approval rejection record `EXECUTE: BLOCKED`.
- Rejected results return `audit_complete=false`, `audit_ok=false`, and `runtime_ok=false`.
- The regression test asserts that no PASS event is present for a rejected request.
- The HTTP execute endpoint remains HTTP 503 / BLOCKED before request-body consumption.
- The server remains bound to loopback only.
- Idempotency replay is bound to a canonical request fingerprint; reusing a key with a different payload is a conflict.
- Nested dataclass response values are serialized deterministically.
- Request-schema validation is covered directly without making the blocked HTTP endpoint reachable.
- Bug Hunt evidence lookup resolves the active pull-request number from the trusted GitHub ref.
- WorkflowGuard stores the terminal decision for the same execution key/fingerprint; replay after success, rejection, or failure returns that terminal decision instead of stale RUNNING.
- Repeated finish calls do not append duplicate terminal audit events; finishing an execution that was never started is rejected.
- The idempotency completion query returns false while the workflow decision is RUNNING or UNKNOWN; only explicit terminal states are complete. Generic results without workflow-state metadata retain the existing result-cache behavior.
- Regression tests cover terminal replay, repeated finish, finish-before-begin, and cross-execution key reuse.

## Required fail-closed states
UNKNOWN, SOURCE_REQUIRED, NEEDS_REVIEW, ABSTAIN, and BLOCKED are never promoted to PASS. A rejected execution cannot create an EXECUTE PASS audit record.

## CI Verification
PR CI Gate, Runtime Tests, and Mandatory Bug Hunt must complete successfully on the exact final head SHA. Historical checks on PR #150 or PR #171 do not substitute for this PR's exact-head checks.

## Affected Contracts
- `runtime/app.py` — local execute audit lifecycle and blocked HTTP adapter.
- `tests/test_runtime.py` — rejected-execution audit regression.
- `tests/test_http_canonical_execution_fail_closed.py` — existing HTTP containment regression remains in the branch.

## Risk Classification
High audit-integrity significance. This patch prevents a rejected operation from being represented as successfully executed. It does not authorize or enable execution.

## Negative Tests
- Missing target cannot record EXECUTE PASS.
- Rejected execution remains audit-incomplete and runtime-failed.
- Caller-authored EDITABLE state cannot pass the HTTP boundary.
- HTTP body is not parsed by the blocked legacy route.

## Unresolved Findings
- Server-owned canonical PlanModel and ConstraintMap registry remains unimplemented.
- End-to-end source identity, approval, impact analysis, controlled editing, post-edit diff, final validation, and audit integration remain incomplete.
- TLS/authentication and remote access remain unimplemented; remote access stays disabled.
- Windows/AutoCAD host tests remain NOT_RUN.

## Final Decision
The false-PASS audit regression is corrected in this branch while the legacy HTTP endpoint remains BLOCKED. This is an implementation candidate only; exact-head CI and human review are required before merge.
