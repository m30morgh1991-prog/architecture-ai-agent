# Bug Hunt Evidence — PR 191 Superpowers Adoption Policy

## Scope

Documentation-only adoption policy for selected Superpowers engineering practices. The change defines when to use planning, TDD, systematic debugging, code review, isolated branches, and verification-before-completion. It preserves the repository's existing GitHub/REAL CI Green Gate, Fail-Closed behavior, review/approval rules, architecture contracts, and Golden DWG immutability.

No application/runtime code, dependencies, CI workflows, permissions, secrets, PlanModel, ConstraintMap, BIM contracts, CAD behavior, Golden DWG assets, or H-stage state are changed.

## Bug Hunt

Review focused on accidental workflow authority escalation, false security claims, hidden dependency introduction, weakening of existing gates, and unintended product-scope changes.

## Findings

- The policy explicitly classifies Superpowers as a development methodology, not a SAST/security scanner or proof of correctness.
- Adoption is limited to engineering workflow practices; no package installation or runtime integration is claimed.
- Existing repository controls remain authoritative, including exact-head REAL CI and independent review requirements.
- The policy prohibits self-approval, branch-protection bypass, false PASS promotion, and mutation of Golden DWG assets.
- Parallel-agent and worktree practices are conditional on actual environment support; no unavailable capability is claimed as executed.

## Root Cause

The project benefits from a repeatable coding-agent engineering process, but adopting a general-purpose workflow toolkit without explicit boundaries could accidentally create a competing source of truth or imply capabilities/security assurance that it does not provide. This policy adopts only the useful practices and explicitly subordinates them to existing project governance.

## Regression

- Superpowers guidance cannot replace or weaken repository rules.
- A local test or agent assertion cannot replace completed required CI on the exact PR head.
- UNKNOWN, SOURCE_REQUIRED, NEEDS_REVIEW, ABSTAIN, and BLOCKED cannot become PASS without evidence.
- A clean heuristic review cannot be called a security PASS.
- No new runtime dependency, workflow permission, external service, or telemetry is introduced.
- Established PlanModel, ConstraintMap, BIM, MVP, and Golden DWG decisions remain unchanged.

## Required fail-closed states

UNKNOWN, SOURCE_REQUIRED, NEEDS_REVIEW, ABSTAIN, and BLOCKED remain unresolved and never become PASS without the defined evidence.

## CI Verification

Fresh PR CI Gate, Runtime Tests, and Mandatory Bug Hunt are required on the exact PR #191 head SHA. No historical run or other PR's green result substitutes for exact-head verification. Pending or missing checks are not green.

## Affected Contracts

- `docs/development/superpowers-adoption-policy.md`
- Development workflow governance: planning, TDD, debugging, code review, and verification.
- Existing GitHub + REAL CI Green Gate and Fail-Closed rules are preserved, not modified.

## Risk Classification

Low documentation/governance risk. The principal risk is treating a workflow methodology as a security tool or allowing it to supersede project-specific controls; explicit prohibitions in the policy mitigate this risk.

## Unresolved Findings

- The effectiveness of the adopted practices must be evaluated through subsequent implementation work; this PR does not itself demonstrate productivity or defect-rate improvement.
- Independent review and exact-head CI remain required before merge.

## Final Decision

Documentation-only process adoption. Safe to evaluate through subsequent work if the exact-head CI and repository review requirements pass. No runtime, security certification, legal, CAD, or stage authority changes.
